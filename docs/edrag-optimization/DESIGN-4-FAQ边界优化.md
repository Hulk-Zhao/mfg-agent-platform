# DESIGN-4 — FAQ 边界优化评估（L1 速查卡 vs RAG 完整内容）

> 2026-10-18，Hulk 报障截图：问「怎么报销」与「我要报销，怎么操作」
> 得到一字不差的相同回答（都是 QP-FIN-002「费用报销时效」一句话，
> 0ms）。本文档记录根因诊断、方案权衡与待决策项。

## 1. 根因诊断（三层，均有数据证据）

### 1.1 语料结构层（主因）：两张语料面严重不对称

| 语料面 | 形态 | 财务报销域内容 |
|---|---|---|
| `kbqa_policy`（L1 源） | 48 条**单事实速查卡**，全部 <60 字（最长 54 字），16 部门 × 3 条 | **仅 1 条**「费用报销时效」 |
| Milvus `enterprise_faq`（L2 源） | 完整文档切片（常见问答.md / 操作细则.md / 管理办法.md） | 报销单怎么填、进度怎么查、单据职责、填写规范……**实测 3+ 条相关** |

「我要报销，怎么操作」含「报销」→ L1 命中唯一相关行 → **score 1.0 直接短路返回**，内容更完整的 RAG 永远走不到。用户追问「怎么操作」没被满足，正是这个短路的直接证据。

### 1.2 算法层：单关键词打满 + margin 失效

实测四个问法全部 `score=1.000`：

| 问法 | score | 命中 |
|---|---|---|
| 怎么报销 | 1.000 | QP-FIN-002 |
| 我要报销，怎么操作 | 1.000 | QP-FIN-002 |
| 报销流程是什么 | 1.000（runner_up 0.028） | QP-FIN-002 |
| 报销单怎么填 | 1.000 | QP-FIN-002 |

「报销」一词即拿满：关键词×2（2字）+ 标题×3 + 内容×1 = 8 分 / 6 分封顶。
评分对「问题问的是哪个方面」（时限 / 流程 / 材料）**零感知**；
margin 双闸在相关语料仅 1 条时失效（runner_up≈0.03）。

### 1.3 链路层：L1 在意图路由之前，命中即短路

链路顺序 L1 → miss 才路由 → RAG/direct。DESIGN-2 的 direct 分流
对 L1 命中问题无效——「怎么操作」连路由都到不了。

## 2. 方案权衡

| 方案 | 做法 | 0ms 保留 | 立即生效 | 主要风险 |
|---|---|---|---|---|
| A. 补 L1 语料 | 财务域补流程/填单/进度等速查卡 | ✓ | 数据运营 | 治标：速查卡结构答不了复合问题；补到何时是个头 |
| B. 复合问题路由到 RAG | 「怎么操作/怎么填/流程/步骤」模式词 → **跳过 L1** 走 RAG | 部分 | ✓（Milvus 内容现成，已实测） | 0→2.6s 延迟；模式词误伤（「年假怎么休」含"怎么"但 L1 答得好） |
| C. 晋升管线运营 | 用户点赞 RAG 好答案 → publish 进 L1 | ✓（渐进） | 慢热 | 依赖用户点赞行为；需前端引导 |
| D. L1 附相关制度 | 命中行作答 + 同 dept 其他行摘要附尾 | ✓ | ✗ | 同部门其他行也是速查卡，信息量有限；依赖 A |

### 2.1 判断：截图场景本身就是晋升管线的经典案例

RAG 对「报销单怎么填」有优质答案（常见问答.md 第20段）→ 用户点赞 →
草稿 → publish → 进 `kbqa_faq` → 下次同问 0ms 直答。
**晋升管线（ADR-001）正是为解决这种长尾收编而建，现在缺的是运营。**

### 2.2 核心权衡：0ms 答偏 vs 2.6s 答对

强批判立场：**「0ms 答偏」比「2.6s 答对」更糟**——演示场景里用户
追问就是没满足的直接信号；答非所问还带「制度直答」绿色角标，
比诚实的 RAG 检索更有误导性（用户以为这就是制度全部内容）。

1. **路由边界**：所有「怎么X」都走 RAG（激进方案，接受 0ms→2.6s 换准确度）
2. **语料补充**：16 个部门各补 1 条流程概要
3. **迭代范围**：B + A + C 全做

## 3.1 交付内容

**B. how_to 让位路由**（`kbqa_intent.route` 新增 `how_to` + `kbqa.answer` 重排）

- 判据：归一化后含 怎么/如何/怎样/咋办 → `how_to=True`
- L1 命中 **且** 非 how_to → L1 直答（0ms 不变）
- L1 命中 **且** how_to → 让位 RAG（Milvus 完整文档综合）
- **域外 how_to（「怎么写诗」）仍走 direct**——不白跑 Milvus
- **RAG miss 回落 L1**：半份答案也是答案，但契约里必须说清
  「未在知识库中找到该问题的完整流程说明」

前置验证（防误伤）：Milvus 对原本 L1 能答的 9 个主题 probe，**9/9 有内容**
（top score 0.64-0.67），方案可行。

**A. 16 条流程概要速查卡**（id 49-64，`seed_v3.sql` + `seed_kbqa.sql` 双种子同步）

每部门 1 条步骤序列型卡片（如 QP-FIN-004「费用报销流程」：填单并附发票→
部门主管审批→财务审核→超权限报总经理→付款至工资卡）。

**A'. 配套算法修正：维度衰减**（这一步不补的话 A 白做）

补完语料后实测：6/6 流程类问法全是 `score=1.0 / runner_up=1.0 /
margin=0 → ambiguous_margin`——**流程卡与单事实卡都打满 1.0 失去区分度**，
16 张流程卡还因共享「流程」二字互相打满。两处修：

1. 维度词（流程/步骤/操作/办理）**从主题匹配中剥离**，只参与维度判定，
   不贡献关键词分与标题分
2. **对称衰减** ×0.8：问流程时压单事实卡，问事实时压流程卡。
   0.8 > 阈值 0.70（被压侧仍是候补），同时把 margin 拉到 0.2 > 0.15

修正后实测：流程类 10/10 命中对应流程卡，单事实类 8/8 命中原卡。

**C. 点赞文案运营化**：「👍 有帮助」→「👍 答得好？收进直答库」，
title 说明点赞=进审核队列→过审后 0ms 直答。只写「有帮助」用户不知道
点赞的作用，晋升管线就收不到素材。
