# DESIGN-2 — kbqa 意图路由（L1 miss 后分流：RAG 检索 vs 域外直答）

> ADR-001 迭代增量。起因：域外问题（天气/闲聊/写作）当前也走完整
> Milvus 检索 + LLM 链路，白花 1-1.5s 检索延迟。目标：L1 未命中时先做
> **零延迟意图分流**，域内进 RAG、其余约束 LLM 直答（限长 + 指引）。

**决策记录（Hulk，2026-10-18 22:30 确认）**：
1. 「都不命中」默认 = **约束 LLM 直答**（参考 EduRAG：LLM 思考模式关闭），
   不是保守走 RAG。即一跳生成，LLM 在约束 prompt 下自行决定答法
2. 范围 = 意图路由 + **Milvus/BGE-M3 启动预热**一起做
3. 域外模式词表**砍掉**：两种 direct 场景路由价值相同，只保留域内词表
   做「保出处通道」的质量守卫；域外/兜底只差日志标签

## 1. 现状实测（2026-10-18，本机，冷/热混合）

| 场景 | L1 匹配 | search_kb | L2 全程 | 结论 |
|---|---|---|---|---|
| 域内-模糊（"车间温湿度记录保存多久"） | 0.4ms | 2059ms | 2722ms | 域内必须保 RAG |
| 域外（"今天天气怎么样"） | 0.3ms | 1091ms | 2617ms | 检索纯浪费，可省 |
| 域外（"帮我写一首诗"） | 0.3ms | 1458ms | 2530ms | 同上 |
| 冷启动首问 | — | 10659ms | 2594ms | BGE-M3 现加载，另题（§6） |

派生结论：**「LLM 分类意图」方案不可行**——单次 LLM ~1.4s > 要省的
search ~1-1.5s，负优化。路由判定必须零延迟 → 词表是唯一 viable 方案。

## 2. 方案：词面意图路由（零延迟）

插入点：`kbqa.answer()` 中 L1 miss 之后、L2 `_answer_rag` 之前。

```
L1 FAQ 命中 ──→ channel=faq（0.4ms，现状不动）
      │ miss
      ▼
意图路由（域内词表，sub-ms）
      │
      ├─ 命中域内词 ──────→ L2 RAG 全链路（channel=rag，现状不动）
      │
      └─ 其余（域外/都不命中）→ 约束 LLM 直答（channel=direct，新增）
                            · 不调 search_kb（省 1-1.5s）
                            · thinking=disabled 实测裸调用 ~1.0s
                            · prompt 四约束（§2.3），max_tokens 200
                            · 仍走 L0 缓存（同问秒回）
```

### 2.1 域内词表构建（数据驱动，定稿 122 词 + 21 拉丁缩写）

来源：`kbqa_policy` 137 个人工标注 keywords 系统比对 + 正文口语说法核验
（只收正文有命中的：打卡/出差/转正/门禁/薪资/车间）。定稿时补回过三个
漏词：账号安全（关键词列有）、订单/资产/升级（销售/SLA 域真实问法）。

**刻意不收的词**（泛词误判面大，且域内伴生词已覆盖真实问法）：
计划/版本/取消/责任/响应/需求/通道/结算/释放/循环——"减肥计划"
"游戏结算"类误判的代价只是多走 1.5s 检索，但词表要的是信号纯度。

**语料答不了的不收**：工资/绩效/婚假/产假/温湿度/保存在 48 行正文
零命中——收了下场也是 RAG→miss，不如让 direct 诚实指引对口部门
（e2e 实证：「车间温湿度记录保存多久」direct 回答正确，语料确实没有）。

拉丁缩写（VPN/ECN/MES/SIP/MRB/8D/IQC/COA/TPM/MSDS/EVT/DVT/PVT/
FIFO/SLA/EAM/WMS/NPI/CPK/SPC/EHS）走词边界正则，防 "MES" 命中 "TIMES"。

### 2.3 直答 prompt 四约束（限长 + 指引 + 防幻觉）

1. 相关问题但无答案 → 明说超出已掌握范围 + 指引对口部门
2. 无关问题（天气/闲聊）→ 一句话说明身份 + 列举可帮方向
3. **禁止编造制度条款/数字/文件名**（幻觉红线）
4. 100 字以内

## 3. 契约与配置（增量）

- channel 新增 `direct`（前端角标「助手直答」灰色/紫色）
- 契约字段**零新增**——路由原因进日志，不进契约（契约已够胖）
- 配置：`KBQA_DIRECT_ENABLED`（总开关，默认 true）、`KBQA_DIRECT_MAX_TOKENS`（200）
- `/api/v2/kbqa/stats` distribution 自动多一个 direct 计数（无改动）

## 5. 验收标准（全部达成，见 DELIVERY-2）

1. 单测：域内词→rag；域外→direct；空/纯标点（含全角）→保守 RAG；拉丁词边界；长词优先；词表快照 ✓
2. 单测：direct 契约形状（无 sources/confidence=None/degraded 语义/channel 值）✓
3. 单测：路由层零外部调用（search_kb/get_llm/llm_available 装炸弹不炸）+ 1000 次 < 100ms ✓
4. 端到端：域外问题全程 < 2s（现状 2.6s）；域内问题通道行为不变 ✓
5. 回归：全量 pytest 绿；L1/L2 存量测试语义不动（R 组用例改为域内词查询 + 缓存隔离）✓

## 6. 已实施（原"同迭代可选"，Hulk 已确认一起做）

- **Milvus/BGE-M3 预热**：`demo/api.py` lifespan 启动时 daemon 线程预热

  体验优化不是依赖。实测 direct 路径本身不依赖 search_kb，冷启动期间
