## 1. 为什么「植入」是低成本：同构是设计出来的，不是巧合

PRD D1 裁决「回放优先 + 字段级同构」时，就把真实链路的契约钉进了回放数据。QA 独立验证（10 项全 PASS）证实了三层同构：

| 回放层字段 | 真实链路来源 | 同构证据 |
|---|---|---|
| `steps[]` 六键（step/thought/tool/args/summary/ok） | `v2/agents/agentic.py::AgenticStep.to_dict()`（ReAct 循环每步留痕） | `tests/demo/test_replay_pipeline.py` 断言键集**相等**；`tool` 取值 ⊆ `AGENT_TOOLS_META` |
| `conclusion{answer,data_used,needs_hitl,hitl_slot,data_gaps}` | `agentic.py` L272-279 智能体最终 JSON 契约 | 同上，键集断言 |
| `trace / filter_explain / ontology_gain / hits` | `services/case_qa.py` / `case_search.py` 真实检索响应字段 | 字段同名同构（架构 §2.1 逐条给出 file:line） |
| `channel=faq + sources[]` | `services/kbqa.py::_contract` L1 命中直答契约 | 答案照抄 faqs 原文，`sources` 结构一致 |
| `dag / hitl_slots` | `scenarios/customer_complaint_v2.yaml`、`spc_anomaly_v2.yaml` 真实场景 DAG | `validate.py` 第五类校验做 DAG↔YAML 机械对回 |
| HITL 工单 | **已经是真实的**——种子工单落在 `WorkflowEngine`（`data/mfg_agent.db`），走 `GOVERNANCE_SLOTS` 治理链 | QA 实测：幂等、槽位/审批角色与 YAML 全等 |

**推论**：把回放数据换成真链路输出，前端 `agentPanel/knowledgeCard` 一行不改即可渲染——T18 真机已证「同一组件吃两种来源」的设计成立（`source: live｜replay` 仅徽标不同）。

## 2. 三阶段植入路径

### 阶段一 · 实时链路开关（P1-1，已在架构预留）——约 2–3 人日，风险低

| 项 | 内容 |
|---|---|
| 做什么 | 改造屏加「实时链路」入口：仅 `llm_available()`（`demo/api.py` 既有降级先例）为真时可用；走既有 `POST /api/v2/query`（TwoLevelRouter → 场景 DAG / 域智能体）+ SSE `/api/v2/events`；事件流映射到同一 `agentPanel`（`source:"live"`） |
| 后端工作量 | **≈ 0**—— orchestrator / 场景 DAG / 域智能体 / SSE 事件流全部现成 |
| 前端工作量 | 入口按钮 + 门控 + SSE 事件 → steps/conclusion 的映射函数（约 1.5 天）；断线/超时降级回回放形态 |
| 关键风险 | LLM 延迟与幻觉 → **回放保持默认**，实时作为「加演」；真链路结论不可复现，演示话术只讲结构不讲具体数字 |
| 验收 | 同一问句：回放与实时渲染同一面板、字段键集一致（结构断言）；LLM 不可用时入口禁用且文案如实 |

### 阶段二 · 单场景真链路试点（建议 S5 客诉 8D）——约 1–2 人周，主要是数据接入

| 项 | 内容 |
|---|---|
| 做什么 | S5 的协同面板数据源从 `agent_replays.jsonl` 换成真实 `customer_complaint_v2` DAG 运行结果；同根因案例从 `cases.jsonl` 换成真实案例库检索（`case_search` 服务已在平台内运行，180 案例 + 本体 226 词条 + AclCompiler 双层授权全是现成的） |
| 数据接入 | `contracts/data_source.py::DataSource` 本就支持 SQLite/MySQL 切换——把 demo 装载层的 15 个对象换成真实业务表（客诉单/检验批/工单/批次/设备），**字段名按 ISA-95 对齐是 T01 规格的既有约定** |
| 单据号替换 | 回放包内 `DEMO-*` 引用换成真实单据号——生成器按 id 派生的纪律（不手抄第二份）保证换源只动 `gen.py` 的数据入口 |
| HITL | 植入后天然真实化：智能体发起 → 真实工单 → 真实岗位处理（治理链已就绪，种子只是演示上下文） |
| 关键风险 | 真实数据质量（缺字段/脏数据）→ 智能体回答必须保持「查不到就说查不到」的 `data_gaps` 诚实纪律（契约已内嵌） |

### 阶段三 · 生产化加固——按平台路线图排期

- **trace 持久化**：真链路的 steps 目前随响应返回，生产应落库（供审计与回放对照）；回放层即天然的「期望形状」样本。
- **并发与限流**：域智能体 MAX_STEPS=8 + 工具 45s 超时已有防卡死；生产需加并发上限与按岗位限频。
- **回放↔实时的对照验收**：同一问句双跑，断言「键集一致、引用可解析」——把 M3（对账率 100%）从演示纪律升级为持续验收。
- **权限**：五访客 readonly 换成真实岗位令牌即可，`permissions.yaml` 持槽判据 / `workflow_scope` / `AclCompiler` 全部同源，无需改。

## 3. 差距清单（逐条：差距 / 影响 / 代价）

| # | 差距 | 影响 | 代价 | 风险 |
|---|---|---|---|---|

## 4. 结论与建议

1. **架构上不存在「重写」**：同构是 PRD D1 的硬约束并被测试钉死，植入是「接数据源 + 开开关」，不是新项目。
2. **推荐顺序**：阶段一（实时开关，2–3 天，演示价值立现）→ 阶段二（S5 单场景真链路试点，1–2 周）→ 按试点结果决定是否铺开到其余五屏（组件与模式已验证，复制成本递减）。
3. **两条铁律植入后不变**：智能体只发起 HITL 永不放行；无引用不输出、查不到就诚实声明数据缺口。
4. **前置条件**：阶段二开工前需明确真实客诉/检验数据的接入源与脱敏口径（涉密字段走既有 `redaction_rules.yaml`）。

> 信息来源：本文全部判断基于代码实证（`agentic.py`/`orchestrator`/`case_search`/`kbqa`/`workflow.py`/`data_source.py`）与 T16–T20 的 QA 独立验证报告（10 项 PASS + 全量 1560 passed）；无拍脑袋项。
