## 2. 六屏导览

### 2.1 工作台（默认屏）
- 欢迎区 + **角色切换器**（总经理 / 制造经理 / PQE / 物控 / 业务）：切换影响预警摘要统计范围与视角描述（演示语义）
- **今日预警摘要**：SPC CPK 越限 / 缺料预警 / 订单履约风险 / HITL 待审批四张计数卡
- **待办中心**：HITL 挂起项——**真实取自 WorkflowEngine 待办队列**，含 SLA 倒计时条、同意/驳回（真实回写）/ 详情跳转；后端离线时展示演示数据并标注
- 快捷入口：智能问数 / 订单履约看板 / HITL 审批中心

### 2.2 订单履约看板（演示数据，页面标注）
- 订单状态管道：已下单→计划→采购→生产→质检→发货，各环节计数与占比条
- 风险订单卡片：延期风险天数、缺料关联（锡膏 M7020/千住金属、PCB BATCH-A-1008/深南电路）、客户等级（S/A/B）、履约进度条
- 部门协同网格：16 部门 → 5 域组（制造/品质/供应链/设备/业务），各域今日待办/已闭环/超时计数与小计

### 2.3 智能问数（核心屏，真实后端链路）
- 对话式界面 + 5 个 V1 场景快捷问题 chips
- **Agent 执行过程可视化**：SSE 订阅 `/api/v2/events`，实时渲染节点流水——business 路由 → confirm_stop → 三域并行 fan_out（品质/供应链/设备，三列并行展示）→ fan_in 汇聚 → fa → workflow（影响评估工单）→ hitl ×2 → report；每节点显示耗时、状态（ok/degraded）、tool 调用明细（SQL 摘要 / RAG 检索 / LLM）
- **结果区**：结构化简报（评级 pill / 各域结论 / 工单）+ **provenance 折叠面板**（SQL 原文、命中行数、表、脱敏标记、节点耗时 chips）+ degraded 横幅（"LLM 不可用，模板化结论，可人工复核"）
- **HITL 待确认卡片**：对话流内渲染，审批人/工单号/可选动作 + 同意/驳回（真实回写工单状态）
- **人工兜底**：超出场景范围的问题（如"今天锡膏批次有问题"）→ 转人工兜底工单卡片，明示"人工兜底是平台设计的一部分"
- 后端离线：明确提示"后端离线——当前为演示模式"，预置演示结果回放（11 节点动画 + 同构结果卡，标注"演示回放"）

### 2.4 预警中心（演示数据，页面标注）
- 类型徽标：SPC 越限 / 缺料 / 订单临期 / 设备告警；等级 P1/P2；状态：待处置/处置中/已闭环
- 每条预警的**联动部门标签**（体现多域协同设计）；支持按类型筛选

### 2.5 报告中心（演示数据，结构复刻 CLI demo 真实输出）
- **内部简报 vs 对客脱敏报告同屏对比**：脱敏词高亮标注（悬停可见禁词原文，如"计划内暂停 ← 停线"）
- 脱敏映射表（对应 node_registry.FORBIDDEN_WORDS 六组映射）
- 报告版本留痕列表（v1.0 初版 → v1.1 脱敏词表修订 → v2.0 当前版本）

### 2.6 HITL 审批中心（真实工单）
- 待审批列表：**真实取自 WorkflowEngine 待办队列**（后端离线用演示数据并标注）
- 详情：工单上下文（run_id/线体/型号/FA 评级/预估复线/受理人）、**SLA 倒计时进度条**（停线工单 2h SLA，实时刷新，≤15% 转红）、处理历史（状态机留痕）

## 5. 已知限制

1. **已注册场景仅 line_stop_v2**：5 个快捷问题中只有停线问题命中场景，其余走"人工兜底工单"（这是平台当前真实行为，UI 已明示，非缺陷）。

3. **看板/预警/报告为演示数据**：生产接入需替换为真实 ERP/MES 数据源（按 V2 DataSource 契约接入后同屏切换）。

## 模型接入（DeepSeek，替代本地 Ollama）

- 直接复用系统环境变量 `ds_url` / `ds_key`；`LLM_PROVIDER=deepseek`（留空时自动识别 DS_KEY）
- 统一使用快模型 `deepseek-flash`；**非推理节点默认关闭思考**（`thinking.type=disabled`）：意图路由 / 报告生成 / Text2SQL SQL 生成
- FA 根因分析保留**轻量思考**（`reasoning_effort=low`），兼顾质量与速度
- 实测优化：L1 意图链路 40.8s → **2.3s**；L0 停线链路约 30s → **9.5s**（FA 7.4s + 报告 1.5s）
- 调整方式：改 `DS_MODEL_L1/DS_MODEL_L2`，或调用 `get_llm(..., thinking="disabled"|"low"|"high")`
