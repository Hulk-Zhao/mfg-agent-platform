# HITL 角色协作与处置动作设计（V2.1）

> 背景：人工确认卡片原来只平铺四个动作标签（退货/换货/特采/挑选），没有回答"谁有权发起、谁必须会签、影响什么、谁来执行后续"。
> 本文按**工厂各岗位视角**重新设计，并说明 v1 已落地范围与后续演进。

## 1. 设计原则

1. **动作由业务角色定义，不由系统定义**：每个动作必须回答四件事——谁发起（propose）、谁必须会签（cosign）、影响什么（impact）、后续谁执行（followup）。
2. **数据缺口不阻塞决策，但必须显式标注**：缺数据时给出"缺少数据源"提示，绝不臆造数字或结论。
3. **决策必须留痕**：决策项 + 决策依据 + 审批人 + 时间 + 状态迁移，全部写入工单 history，可审计。
4. **高风险动作强制填写依据**：特采/降级使用/报废/闭单/停机/加急等，必须写清理由，否则不允许提交。

## 2. 各岗位在决策中的关注点

| 角色 | 最关心什么 | 在决策中提供什么 | 常见必须会签 |
|---|---|---|---|
| **SQE**（供应商质量） | 来料缺陷等级、供应商责任、特采风险 | 不合格判定、供应商历史、SCAR 依据 | 退货/换货/特采的发起方 |
| **PQE**（过程质量） | 制程能否补偿、SPC 风险、加严检验成本 | 参数补偿能力、挑选标准、检验方案 | 特采、挑选、降速运行 |
| **QA / 质量经理** | 客户特殊要求、体系合规、质量成本 | 客户规格确认、特采终批、8D 关闭 | 特采、降级使用、8D 关闭 |
| **采购** | 交期、成本、供应商关系与索赔条款 | 新批次 ETA、替代供应商、索赔口径 | 退货、换货、挑选费用分摊 |
| **计划** | 排产窗口、订单优先级、停线损失 | 可插单窗口、换产成本、交期影响 | 复线、停机窗口、加急 |
| **物控** | 库存、齐套、替代料可用性 | 可用库存、在途、替代方案 | 退货/换货后的锁批与补料 |
| **生产 / 制造** | 产能、工时、操作可行性 | 挑选工时、停线损失、复线条件 | 复线、挑选、停机 |
| **业务** | 对客承诺、合同条款、客户等级 | 交期口径、客户沟通策略 | 对客 ETA、客诉回复、分批出货 |
| **工程 / 设备** | 参数恢复、备件到位、设备可靠性 | 停机窗口、备件清单、参数基线 | 复线、停机窗口、降速运行 |
| **财务** | 成本归集与损失确认 | 金额阈值触发审批、核销口径 | 报废、重大退货 |

## 3. 五个场景的决策设计

### S2 来料异常 · 退换货/特采决策（6 个动作）

| 动作 | 发起 | 必须会签 | 影响 | 后续执行 |
|---|---|---|---|---|
| 退货 | SQE | 采购 | 交期 +3~5 天；费用供应商承担 | 采购索赔 / 物控锁批 / 计划重排 |
| 换货 | SQE | 采购 | 交期 +5~10 天；需评估替代料 | 采购跟催新批次 / 物控锁批 / 计划调整 |
| 特采（让步接收） | SQE | PQE + 业务 + QA | 质量风险上升；需加严检验与批次追溯 | 加严检验 / SPC 加密 / 客户告知（按合同） |
| 挑选/全检 | PQE | 生产 + 采购 | 工时成本上升；交付可控 | 制定挑选标准 / 生产排工时 / 供应商费用分摊 |
| 降级使用 | QA | 业务 | 仅限非功能项；需客户规格确认 | 客户确认 / 追溯标记 |
| 报废 | SQE | 财务 | 成本损失；需补料 | 财务核销 / 采购补料 |

> 关键判断：**特采不是 SQE 一个人能定的**——质量风险由 PQE 评估、客户影响由业务/QA 确认，三方会签后才允许让步接收。

## 4. v1 已落地（本次交付）

- **场景数据**：5 个场景、7 个 HITL 决策点、**25 个结构化动作**（propose / cosign / impact / followup / require_comment）。
- **前端**：
  - 动作按当前岗位权限门控：无权限的动作灰显，提示"需 SQE 发起"；
  - 选中动作后展示**影响**、**会签方**、**后续动作**；
  - 高风险动作强制填写决策依据；
  - 同意前必须先选动作（有动作时）。
- **后端**：
  - 审批接口新增 `decision` 字段，工单 history 记录 `决策：<动作>；<依据>`；
  - 降级原因按"数据缺口 / 服务未就绪"分别表述，不再错误归因。

## 5. 后续演进（不在本次范围）

1. **后端强制校验审批角色**：当前仅为前端门控；生产环境需在 approve 时校验审批人岗位是否在动作的 propose 名单内。
2. **多人会签**：当前记录"会签方"但为单签；后续支持按 cosign 列表逐个签署（任一驳回即终止）。
3. **动作自动触发后续工单**：如"退货 → 采购索赔单""挑选 → 生产工时工单""报废 → 财务核销单"。
4. **IM 卡片回写**：企业微信卡片按钮携带 `decision`，实现群内审批闭环。
5. **金额阈值配置化**：报废/退货按金额触发财务/管理层审批（需财务提供阈值表）。
