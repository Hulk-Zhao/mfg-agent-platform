2产品概述

2.1 定位

mfg-agent-platform 是一个跑在厂里的多智能体协同平台。它要解决的事情很具体：现场一出异常——停线、来料不合格、客诉——信息散在五六个系统和无数个微信群里，凑情况靠打电话，跨部门对一个口径要半天。

平台的做法是把「提问 → 路由 → 多域并行取证 → 工单 → 人工会签 → 对客报告」这条链路固化下来：18 个智能体分工取证，人只在会签点出现，每个数字都能溯源到 SQL。基本盘是 18 个智能体（17 个领域 + 1 个办公）、7 个声明式协同场景、31 个演示岗位 / 12 屏门户、1204 个离线确定性测试（CI 跑 Python 3.11/3.12/3.13 三个版本）。

演示门户
原生 HTML/CSS/JS 零构建，31 岗位免密选登，12 屏按岗位收敛，SSE 实时事件流驱动
统一 API
FastAPI：query / events / workflow / dashboard / im 回调，统一响应信封 + SSE 事件流
双协议接入
MCP Server（stdio JSON-RPC 2.0）与 A2A（Agent Card + message/send），治理链同源

2.2 解决的三个问题

进度散落。订单到哪一步了，答案在 ERP、MES 和各个部门群里各有一份，跨部门同步以天计。平台的做法是多域 Agent 并行取证，SSE 事件流实时呈现，秒级触达。

取数靠人。问数目前的常态是问人、导 Excel、写 SQL，口径还不统一。平台提供 Text2SQL 八道防线加指标库口径统一，数字带 SQL 溯源。

跨部门取证靠打电话。停线、缺料、客诉的闭环周期长，是因为取证本身是人工接力。平台用 YAML 场景 DAG 自动编排多域取证，工作流引擎驱动工单与会签。

3.2 三条设计主线

  1. 确定性流程走工作流引擎，LLM 只做理解、推理、分析、生成、汇总。审批、通知、升级、状态流转这些动作，永不由 LLM 触发。
  2. 数据质量优先于智能能力。没有数据来源时输出 data_gap 并强制人工确认——缺数据也要人拍板，而不是编一个结论。
  3. 所有智能体行为可审计。每次检索、问答、SQL、审批都落审计，数字结论强制 provenance 溯源。

场景声明式编排

scenario_id: line_stop_v2

  - {id: mfg_confirm, agent: manufacturing}

5.3 治理层

治理层是这个产品花力气最多的地方，也是和「套壳问答」拉开差距的部分。分五块讲。

5.3.1 声明式权限目录

v2/data/permissions.yaml 对标 Huly controlled-documents 范式：8 个 HITL 槽位 × 3 个动词（propose 发起 / cosign 会签 / approve 终批）= 24 条权限，32 个治理角色，全部声明在 YAML，业务代码零硬编码。

  • 构造期自检：Agent 身份角色只允许 *.propose，持有 *.approve 直接启动失败。
  • 会签纪律：一人一签、并发幂等，缺一不可，绝不自动放行。
  • 未识别角色或权限一律 fail-closed。

5.3.2 待办可见性（同源于权限目录）

规则行为
令牌为准Bearer 令牌裁决角色；role 查询参数只能收窄不能扩宽，传他人角色 → 403
mine / domain 二分mine = 当前轮到我（可动作）；domain = 治理域内待观察（只读）
无治理职责岗位返回空队列 HTTP 200——「本来就没有你的活」≠「无权查看」（403），两种状态可区分
跨域工单详情返回 404 而非 403（403 会确认工单存在，404 不泄漏 ID 空间）
MCP / A2A 同口径工具参数里的 roles 无法覆盖真实身份

5.3.3 数据范围与脱敏

v2/data/data_scope.yaml 声明式裁决四个 /dashboard/* 加 /dashboard/drill：无令牌 401、未登记看板 403（fail-closed，谁也用不了，刻意如此）、岗位不在 allow_roles 403（不返回 200 空数据）。订单看板客户身份按岗位脱敏（客户 A/B 稳定代号），排行与下钻同源脱敏；被脱敏的行会移除下钻实体并标 masked——只藏名字留下钻键等于没脱敏。

5.3.5 制造案例检索（本地增强 Agentic RAG）

  • 两段式安全检索：服务端按身份编译过滤条件（ABAC：显式 deny > 全局硬门禁 > 维度 AND > RBAC > 默认拒绝）并下推向量库，过滤在召回前生效；返回前再用关系库 ACL 做第二次授权，走独立代码路径。候选不足时绝不放宽过滤重试：hits == 0 返回空 + hidden_count，宁可少给。
  • 最小泄漏面：无权案例统一 404 CASE_NOT_FOUND_OR_NOT_VISIBLE，不泄漏存在性。
  • 无引用不输出：每条结论挂 (case_id, chunk_id, content_version) 三元组，引用校验器回查，版本不一致即丢弃；相关度低于阈值直接拒答——问「食堂几点开饭」不会得到锡膏印刷答案。
  • 受控词表本体增强：缺陷模式/根因/对策受控编码（DM-SMT / RC-EQP…）归一「同一现象不同叫法」，混合检索 + 确定性重排（状态权重×新鲜度×有效性）。
  • 导出默认拒绝、外发恒定拒绝：可看 ≠ 可带走；CaseAccessAgent 只按受控词表路由申请并留痕，推断不出就明说。
  • 审计链可对账：每次检索/问答落审计（主体/动作/命中数/查询哈希/过滤哈希），只记哈希不记正文，提供一键校验。

6.3 向量检索

双路召回（BGE-M3 dense + sparse）加 BGE-Reranker-v2-M3 重排；后端三实现（内存默认 / ChromaDB / Milvus），VECTOR_BACKEND / CASE_VECTOR_BACKEND 一键切换，零代码改动。

6.4 缓存与降级

Redis 承担会话上下文缓存、查询结果缓存与单 IP 限流；连接失败自动降级为无缓存（探针标记 disabled，不计入 degraded）。

7.2 错误码

HTTP场景设计意图
200 / code=0成功或业务兜底超范围问题 fallback=manual_ticket 是设计的一部分，非错误
400参数非法 / 下钻层级跳级回显 unknown 便于定位
401缺令牌 / 令牌非法或过期看板/下钻/待办/详情一律 fail-closed
403无数据权限 / 验签失败detail 给出谁能看，不返回 200 空数据
404资源不存在或跨治理域不可见刻意不区分：避免确认 ID 存在
409非法状态迁移状态机拒绝（如 closed→running）
500服务端错误（如企微密钥未配置）SQL 拦截/越权/LLM 生成 DDL 等不返回 5xx，降级为兜底 + warnings

7.3 SSE 事件枚举（与 V1 兼容，前端零改动）

agent_start / tool_start / tool_end / llm_start / agent_end（status ∈ ok/degraded）/ fan_in / error；收到 final / error 后结束。

10安全设计

面机制
认证演示门户 31 岗位免密选登；写接口凭 HMAC 签名的岗位访问令牌（8h TTL）；AUTH_SECRET 未配置时生成进程级随机密钥并告警
权限三层（正交）菜单层 NAV_ITEMS[].roles（只管可见性）/ 待办层 workflow_scope.py（HITL 槽位判据）/ 数据层 data_scope.yaml（看板裁决）——三者独立，都在服务端；前端不做权限判断
脱敏字段级脱敏策略 + 排行/下钻同源 + 报告出口禁词表兜底；前端展示「已脱敏 N 项」角标
审计每次 LLM 调用、SQL、审批、通知全量入审计表，只追加不可改
fail-closed未登记看板 403、未识别角色拒绝、无权案例 404、治理库拒非 SQLite
数据主权LLM 与数据组件私有化部署；涉敏推理强制本地；外部 API 仅限脱敏后非敏场景

11性能与可观测

11.1 健康探针

/api/v2/health 跑 5 项探针（业务库 / 治理库 / Redis / 向量库 / LLM），并行执行，总耗时等于最慢一项；TCP 探测共用 0.6s 总预算，localhost 双地址族不翻倍。返回 ok / degraded 加逐项明细。探针不触发编排器初始化，可以给 Docker HEALTHCHECK 高频调用；任一探针抛异常一律收敛为 down，健康检查自身不允许 500。

11.2 降级矩阵

故障行为
LLM 不可用规则路由 + 模板结论 + degraded 标记，数字仍来自 SQL
Redis 不可用自动降级无缓存，探针标 disabled（不计 degraded）
向量库不可用案例检索降级（RAG 通道标 degraded），Text2SQL 主链不受影响
单域超时该域标 degraded 继续 fan_in，不阻断整链
数据无来源data_gap 通道显式提示，前端必须渲染提示条（架构诚实性）

11.3 事件流与耗时

SSE 请求级隔离，消除全局队列并发串话；/api/v2/query 响应含 timings（各节点耗时 ms）与 elapsed_ms，provenance 含每条 SQL 的耗时。

术语含义
HITLHuman-in-the-Loop，人工在环：propose → N×cosign → approve，绝不自动放行
