# 我的看板 · 竞品调研与下钻设计

> 目标：调研主流 BI / 制造运营平台「个人工作台 · 我的看板」的能力形态，并为本平台「工作台 → 我的看板」补齐**卡片级三级下钻**能力，与既有「订单履约看板 / 制造综合看板」共用同一套下钻机件。

---

## 一、竞品调研

### 1.1 调研对象与范围
| 竞品 | 定位 | 「我的看板 / 工作台」能力重点 |
| --- | --- | --- |
| 帆软 FineBI | 自助式 BI | 仪表板内「图表内钻取」（跨层级联）、组件级钻取配置；首页「我的分析」按用户订阅组织 |
| 观远 BI | 一站式智能 BI | 首页「我的看板」支持**多层级/自由下钻** + **面包屑导航**；卡片可点击穿透到明细 |
| Power BI（Service） | 企业 BI | 个人工作区 + 应用内仪表板；卡片支持「聚焦/钻取」与跨页钻取（Drill-through） |
| 金蝶云·星空 / 订单承诺智能体 | 制造业 ERP | 交付类看板按**订单/客户/物料**逐单追踪，逾期归因到工序与缺料 |
| 用友 BIP | 制造云 | 工作台按角色预置 KPI + **逐单追踪 → 逾期归因**；异常卡片直达处置 |
| 飞书 / 钉钉 工作台 | 协同平台 | 「工作台」= 应用聚合 + 待办中心；卡片是**入口**而非分析层 |

### 1.2 竞品「我的看板」范式拆解
综合上表与本次竞品截图（工作台 / 我的看板），可归纳出六条共性范式：

1. **岗位视角切换**：顶部「切换视角」（研发 / 工艺 / 工程 / 计划 / 质检 …），同一工作台按岗位渲染不同 KPI。
2. **KPI 卡为分析入口**：每张 KPI 卡 = 一个指标 + 一个「?」下钻入口（如「近一周有多少订单存在延期风险?」「有多少订单存在延期风险?」）。
3. **卡级下钻**：点卡 → 维度分解 → 单实体明细，且**面包屑逐级返回**（观远/帆软/FineBI 普遍如此）。
4. **问答式下钻**：部分平台把「?」直接接到对话式分析（NL2SQL），用自然语言追问替代固定报表。
5. **待办中心**：工作台内嵌「今日重点关注 / 待办中心」，异常→处置闭环。
6. **人工在环（HITL）**：关键决策在列表内即可审批确认（卡片即详情，减少跳转）。

### 1.3 竞品截图要点（用户提供）
- 顶部：「工作台 / 我的看板」+「切换视角」。
- 「我的看板」4 张 KPI 卡（92.4% / 386 / 5 / 232），每卡一个「?」——**问句式下钻入口**。
- 下方：「今日重点关注」「待办中心」「人工在环待确认」（HITL 任务卡）。
- 结论：竞品的 KPI 卡**既要是"结论"，也要是"追问起点"**，且下钻与待办/审批在同一工作台内闭环。

## 二、下钻交互设计

### 2.1 分层模型（与看板同构）
- **L1｜KPI 卡**：指标值 + 目标/趋势；有指标映射的卡点卡就地进入 L2，卡内「问数」进入协同问数。
- **L2｜维度分解**：按「客户 · 等级 / 型号 / 产线 · 型号」全量分解表（序号 / 维度 / 值 / 目标 / 状态 / 分子 ÷ 分母 / 7 日趋势 / 操作），点行进入 L3。
- **L3｜单实体明细**：大字值 + 逐日明细 + **关联原始记录**；L4/L5（工序/工位）沿用看板既有能力。

### 2.2 面包屑
`我的看板 › OTD 准时交付率 › 华为终端 · S`，左上角「返回二级 / 返回看板」，逐级回退，最末级高亮。

### 2.3 双入口（对齐竞品「卡即入口」）
- **整卡点击** → 就地三级下钻（本次新增）。
- **卡内「问数」** → 协同问数并预填该卡问题（`chat_prefill` → 自动发送）。
- 未配置指标映射的卡：保持原行为——整卡点击即问数。

### 2.4 设计取舍
采用**工作台内就地展开**而非「跳转到对应看板再下钻」：
- 岗位视角下不丢失上下文（不换屏、不丢面包屑）；
- 复用看板既有 `build_drill` 聚合引擎与下钻渲染机件，前端零新增组件；
- 与竞品「卡片即分析入口、面包屑就地返回」范式一致。

## 三、指标映射（L1 卡 → 看板指标）

### 3.1 覆盖原则（阶段二：全角色覆盖）
阶段一仅对 6 个岗位各开启 1 张卡的下钻；阶段二把**全部 31 个岗位**补齐，做到**每个岗位至少 1 张可下钻卡**（共 37 张卡接入）。

- **语义精确对应**优先（如 SQE/采购 → 来料批次合格率、PM/NPI/研发 → 里程碑达成率、CS → 客诉闭环率）。
- 少数无同义指标的岗位采用**就近映射**（见 3.3 注记），口径以"同类待办/流程指标"承接，避免无真实数据支撑的伪指标。

## 三·附、阶段二新增下钻指标（后端 DRILL_DEFS）

阶段二为支撑全角色覆盖，新增 **9 个有真实数据支撑**的指标；其中 4 个为**快照口径**（表无日期列，不做时间窗口过滤，L3 逐日序列诚实留空）：

| 指标 | 看板 | 表 / 口径 | 维度 | 窗口 |
| --- | --- | --- | --- | --- |
| `oee` | manufacturing | production_output · `SUM(oee)/100 ÷ COUNT` | 产线 · 型号 | 有 |
| `production_achieve` | manufacturing | production_output · 实际 ÷ 计划产出 | 产线 · 型号 | 有 |
| `incoming_pass_rate` | quality | incoming_batch · 合格批次 ÷ 批次总数 | 供应商 | 有 |
| `test_pass_rate` | quality | test_records · 通过 ÷ 总数 | 测试类型 | 有 |
| `std_conformity` | quality | std_standard_audit · 符合项 ÷ 审核项 | 型号 · 工序 | 有 |
| `complaint_close_rate` | quality | customer_complaint · 已闭环 ÷ 总数 | 客户 · 型号 | **快照** |
| `material_shortage_rate` | orders | material_inventory · 低于安全库存行 ÷ 总行 | 仓库 | **快照** |
| `milestone_done_rate` | orders | project_milestone · done ÷ 总数 | 型号 | **快照** |
| `task_backlog_rate` | orders | platform_workflow_task · waiting_hitl ÷ 总数 | 流程 | **快照** |

> 引擎增强：`build_drill` 支持**无窗口（快照）指标**——无 `date_expr` 时不加时间过滤，L2 不产 7 日趋势、L3 `daily=[]`（不伪造逐日序列）。
> 实体机制泛化：`_entity_cols` 由显式 `entity_cols` 优先、否则按 `entity` kind（`line_model`/`wo_no`/`customer`/`model`）推导，一套代码支撑 `supplier`/`test_type`/`warehouse`/`wf`/`model+pstep` 等任意维度。

## 四、落地实现

### 4.1 复用（零新增组件）
- 聚合与口径：后端 `build_drill` / `DRILL_DEFS`（L2 分组、L3 逐日 + 原始记录）**完全复用**。
- 渲染机件：`mfgCrumbHtml` / `mfgDrillL2Body` / `mfgDrillL3Body` / `mfgBind` / `loadMfgDrill` **完全复用**。

### 4.2 改动清单
| 文件 | 改动 |
| --- | --- |
| `demo-data.js` | 阶段一：为 6 张 KPI 卡补 `drill:{screen,kpi}`；阶段二：扩到 **37 张卡 / 31 岗位**；`DRILL_META` 补 9 条离线镜像（含 `rows` 数组，镜像真实 L2 值） |
| `screens.js` | 新增 `DASHBOARD_CFG`（宿主容器 = `dash-crumb`/`dash-body`）与 `boardCfgOf()`；`loadMfgDrill`/`mfgBind`/`backDrill` 增加 **host 透传**（`host="dashboard"` 时渲染到工作台容器）；新增 `dashKpiCard()`；`render_dashboard` 接入就地 L2/L3；`render_orders`/`render_mfgboard` 增加 host 复位守卫（避免跨屏残留） |
| `services/dashboard.py` | 通用实体机制 `_entity_cols`（显式 `entity_cols` 优先，否则按 `entity` kind 推导）+ `entity_param_names()`；`build_drill` 支持无窗口（快照）指标；`DRILL_DEFS` 新增 9 个真实指标；`_COL_CN` 补中文表头 |
| `demo/api.py` | 下钻路由改为按 `entity_param_names(kpi)` **通用取参**（不再写死 4 种实体参数名），保留 L4/L5 跳级校验 |

### 4.3 host 透传要点
下钻状态仍存于 `state.screenState.boardDrill`，但带 `host` 标记：
- 工作台内联下钻 → `host:"dashboard"`，`loadMfgDrill` 渲染到 `#dash-body`，面包屑根为「我的看板」；
- 看板内下钻 → 无 host，行为与改造前完全一致；
- 跨屏时守卫逻辑清空残留状态，**不串屏、不误渲染**。
