# mfg-agent-platform · V2 接口文档

> 版本：2.0.0（含 V2 增量：4 场景 + 脚手架对齐）
> 服务入口：`mfg_agents.v2.demo.api:app`（FastAPI）
> 运行：`uv run uvicorn mfg_agents.v2.demo.api:app --port 8004`
> 统一响应信封：`{"code": 0|非0, "data": <obj>, "message": "<msg>"}`（HTTP 层另含状态码，见"错误码"）

---

## 1. 概述

平台把"制造业多智能体协同"封装为**统一查询入口 + 事件流 + 人工在环（HITL）**三件套：

```
用户/IM → POST /api/v2/query ──► TwoLevelRouter（L0 规则 / L1 闭集 / 降级）
                              └► 场景 DAG（YAML 声明式）：
                                   intake → 域判定 → fan_out 并行取证 → fan_in
                                   → workflow 工单 → HITL 人工确认 → report
       GET /api/v2/events ──────► SSE 实时事件流（请求级隔离）
       GET /api/v2/workflow/pending ├─ POST approve/reject（HITL 回写状态机）
```

**离线可跑**：本机无 LLM（Ollama 离线）时自动降级——路由走规则、判定/报告走模板，
结论标 `degraded=true`，数字仍来自 SQL（`provenance` 可溯源），**绝不编造**。

---

## 2. 基础信息

| 项 | 值 |
|---|---|
| Base URL | `http://<host>:8004` |
| 数据格式 | 请求 `application/json`；SSE 响应 `text/event-stream`；企微回调 `application/xml` |
| 认证 | demo 无鉴权；`user_ctx` 由调用方注入（生产应由认证体系填充） |
| 权限模型 | 表级白名单（`TABLE_ACL`）+ 列级脱敏（`SENSITIVE_COLUMNS`，按角色），fail-closed |
| 场景枚举 | `line_stop_v2` / `incoming_quality_v2` / `customer_complaint_v2` / `delivery_status_v2` / `equipment_warning_v2` |

## 3. 端点目录

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v2/health` | GET | 健康检查 |
| `/api/v2/query` | POST | 统一查询入口（路由 → 场景 DAG → 聚合结果） |
| `/api/v2/events` | GET | SSE 事件流（按 `request_id` 订阅） |
| `/api/v2/events/open` | POST | 预开事件队列（消除"先查询后订阅"时序竞态） |
| `/api/v2/workflow/pending` | GET | HITL 待办队列 |
| `/api/v2/workflow/{task_id}/approve` | POST | HITL 审批通过 |
| `/api/v2/workflow/{task_id}/reject` | POST | HITL 审批驳回 |
| `/api/v2/im/wecom/callback` | GET/POST | 企业微信回调（URL 校验 / 消息处理） |
| `/demo-ui/*` | GET | 演示前端静态资源（`demo/ui`） |

## 4. 端点详情

### 4.1 `GET /api/v2/health`

**响应**
```json
{ "status": "ok", "version": "2.0.0" }
```
> 说明：本次未聚合 VectorStore/DataSource 健康（设计 §8.4 U6，P2 可选）。接入见
> `contracts/vector_store.py::ChromaVectorStore.health()`（返回 `{backend, ok, collection_count}`）。

### 4.2 `POST /api/v2/query`

**请求体**
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 用户问题（自然语言） |
| `user_ctx` | object | 否 | 用户上下文；缺省用演示默认 `{dept:"manufacturing", roles:["manufacturing","coordinator"]}` |
| `request_id` | string | 否 | 事件流订阅 id；缺省服务端生成 |

**`user_ctx` 字段**
| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 用户标识 |
| `dept` | string | 部门（参与表级权限判定） |
| `roles` | string[] | 角色列表（`coordinator` 为跨域总控取证角色；`sqe` 可见供应商等敏感字段） |

**示例**
```json
{
  "query": "A型号能发多少货",
  "user_ctx": { "user_id": "u-gm", "dept": "management", "roles": ["coordinator"] },
  "request_id": "req-abc123"
}
```

**响应**（`data` = `OrchestratorResult.to_dict()`）
| 字段 | 类型 | 说明 |
|---|---|---|
| `query` / `run_id` | string | 原始问题 / 本次运行 id |
| `route` | object | 路由结果：`{domain, scenario_key, confidence, level, entities, low_confidence, reason}` |
| `scenario_key` | string\|null | 命中场景；`null` 表示超出范围（转人工兜底） |
| `report` | string | 对客报告（S3/S4；脱敏）或人工兜底说明 |
| `internal_brief` | object | 内部简报（按场景聚合的关键结论） |
| `provenance` | array | 溯源：各域 SQL 原文/通道/命中行/耗时 + 节点耗时 |
| `hitl` | array | HITL 待确认卡片列表（`status=waiting_hitl`，绝不自动放行） |
| `workflow_tasks` | array | 工作流工单列表 |
| `timings` | object | 各节点耗时（ms） |
| `degraded` | bool | 是否处于降级（LLM 离线）模式 |
| `degraded_reasons` | string[] | 降级原因（可审计） |
| `fallback` | string\|null | 兜底标记（`manual_ticket`） |
| `elapsed_ms` / `error` | number\|null / string\|null | 总耗时 / 错误 |
| `request_id` | string | 回显请求 id（用于订阅事件流） |

**响应示例（S4 出货风险，离线 degraded）**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "query": "A型号能发多少货",
    "run_id": "run-xxxx",
    "route": { "level": "L0", "domain": "supply_chain", "scenario_key": "delivery_status_v2",
               "confidence": 1.0, "low_confidence": false,
               "entities": {"product_model": "A型号", "line_code": "SMT-1", "urgency": "normal"} },
    "scenario_key": "delivery_status_v2",
    "internal_brief": { "ATP承诺分析": "A型号 ATP=400pcs，订单需求=3500pcs，缺口=3100pcs，风险订单 2 单", "...": "..." },
    "report": "尊敬的客户：经核实，贵司订单当前受产能与物料因素影响，存在交付风险……",
    "hitl": [ { "kind": "delivery_commit", "status": "waiting_hitl",
                "prompt": "对客交期承诺确认", "approver_roles": ["业务经理"], "task_uid": "wf-xxxx" } ],
    "workflow_tasks": [ { "ticket": { "wf_id": "delivery_risk_flow", "status": "running", "...": "..." } } ],
    "degraded": true,
    "degraded_reasons": ["报告生成 LLM 不可用：模板化 + 禁词表兜底"]
  }
}
```

### 4.3 `GET /api/v2/events`

订阅指定请求的事件流（SSE）。

**Query 参数**
| 字段 | 类型 | 说明 |
|---|---|---|
| `request_id` | string | 必填，`POST /api/v2/query` 或 `/events/open` 返回的 id |
| `wait_s` | number | 最长等待秒数（默认 120，上限 300） |

**SSE 消息**：`data: {<event>}\n\n`，`<event>` 字段见下表；收到 `final`/`error` 后结束。

**事件枚举**（与 V1 完全一致，前端零改动）
| `type` | 关键字段 | 说明 |
|---|---|---|
| `agent_start` | `node, label, icon` | 节点开始 |
| `tool_start` / `tool_end` | `tool, detail` | 工具调用（SQL/RAG/意图识别） |
| `llm_start` | `detail` | LLM 推理开始 |
| `agent_end` | `node, label, summary, status, elapsed_ms` | 节点结束（`status ∈ ok/degraded`） |
| `fan_in` | `node, domains, degraded, summary` | 并行汇聚 |
| `error` | `detail` | 异常 |

**错误**：`404`（`request_id` 不存在或已结束）。

### 4.4 `POST /api/v2/events/open`

**请求体**：`{ "request_id": "req-abc123" }`
**响应**：`{"code":0,"data":{"request_id":"req-abc123"},"message":"ok"}`
> 幂等：与 `query` 内的队列预开共用同一队列。

### 4.5 `GET /api/v2/workflow/pending`

**响应**
```json
{ "code": 0, "message": "ok",
  "data": [
    { "task_uid": "wf-xxxx", "wf_id": "hitl_disposition", "title": "退换货/特采决策确认",
      "status": "waiting_hitl", "priority": "P1", "assignees": ["SQE","PQE","生产"],
      "context": { "run_id": "run-xxxx", "kind": "disposition", "card": { "...": "..." } },
      "hitl_prompt": "退换货/特采决策确认", "sla_due_at": "2026-10-17T02:00:00+00:00",
      "history": [ { "action": "create", "from": "pending", "to": "waiting_hitl" } ] }
  ] }
```

### 4.6 `POST /api/v2/workflow/{task_id}/approve`

**请求体**
| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `approver` | string | `"演示用户"` | 审批人（写入工单 history） |
| `comment` | string | `""` | 审批意见 |
| `final` | bool | `false` | `true` 时终态 `done`，否则回到 `running` |

**响应**：`data` = 更新后的工单对象。**错误**：`404`（工单不存在）、`409`（非法状态迁移）。

### 4.7 `POST /api/v2/workflow/{task_id}/reject`

**请求体**：同 4.6（`final` 忽略）。
**响应**：`data` = 更新后的工单对象（`status=closed`）。**错误**：`404` / `409`。

### 4.8 `GET/POST /api/v2/im/wecom/callback`

- **GET**（URL 校验）：query 参数 `msg_signature, timestamp, nonce, echostr` → 验签+解密 → 回显明文。
- **POST**（消息处理）：解密 → `V2Orchestrator.handle` → 被动回复卡片（XML）。
- **错误**：`403`（验签失败）、`500`（未配置 `IM_TOKEN/IM_AES_KEY/IM_APPID`）。

## 5. 数据模型：`QueryResult`（provenance 项）

`provenance` 数组中，SQL 类条目结构如下（供前端渲染"SQL 原文 + 命中行 + 脱敏标记"）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `channel` | string | `registered` / `metric` / `detail` / `compute` / `template` / `data_gap` / `report` / `workflow` / `hitl` / `rag` |
| `query_name` / `metric_id` | string | 查询/指标名 |
| `sql` | string | SQL 原文（可审计） |
| `row_count` | number | 命中行数 |
| `masked` | bool | 是否触发字段脱敏 |
| `tables` | string[] | 访问的表（权限审计） |
| `domain` | string | 产出域 |

> `data_gap` 条目：`{ "channel":"data_gap", "domain":"rd_engineering", "note":"设计根因：无 BOM/ECN/图纸数据源，未编造结论" }`
> —— 表示"该数据当前无来源"，前端必须显式渲染提示条（架构诚实性要求）。

## 6. 错误码

| HTTP | `code` | 场景 | 说明 |
|---|---|---|---|
| 200 | 0 | 成功 | `message="ok"` |
| 200 | 0 | 业务兜底 | 超范围问题：`data.fallback="manual_ticket"`、`data.scenario_key=null`（**不是错误**，是设计的一部分） |
| 403 | — | 回调验签失败 | 企微回调签名/AES 校验不通过 |
| 404 | — | 资源不存在 | `request_id` 无队列 / 工单 `task_id` 不存在 |
| 409 | — | 非法状态迁移 | HITL 状态机拒绝（如 `closed→running`） |
| 500 | — | 服务端错误 | 企微回调未配置密钥等 |

> 平台纪律：SQL 审核链拦截 / 越权访问 / LLM 生成 DDL 等**不返回 5xx**，而是降级为
> `fallback="manual_ticket"` + `warnings`（防"编得出、没人发现"）。

## 7. 场景与节点（增量）

| 场景 key | 触发词（L0） | 节点序列（简化） | HITL |
|---|---|---|---|
| `incoming_quality_v2` | 来料/IQC/锡膏/批次有问题/COA/不合格 | intake→sqe_assess→[procurement‖planning‖material_control]→fan_in→scar_wf→hitl_disposition→report_incoming | 退换货/特采决策 |
| `customer_complaint_v2` | 投诉/客诉/8D/客户/不良率/华为/围堵 | intake→qa_lead→[pqe_process‖sqe_supplier‖engineering‖business_sales]→fan_in→capa_flow→hitl_d8_close→hitl_complaint_reply→report_complaint | 8D 关闭、对客回复 |
| `delivery_status_v2` | 能发/发货/交期/库存/在途/ATP/出货 | intake→[business_order‖planning‖material_control‖warehouse_atp‖manufacturing_output‖logistics]→fan_in→atp_analysis→delivery_risk_wf→hitl_delivery_commit→report_delivery | 对客交期承诺 |
| `equipment_warning_v2` | 设备/参数/预警/维护/告警/维保 | intake→equipment_check→[maintenance‖planning_window‖engineering_param‖spare_parts]→fan_in→maintenance_flow→hitl_maintenance_window→report_equipment | 停机窗口确认 |

> `line_stop_v2`（既有）节点序列不变，作为回归基线。
