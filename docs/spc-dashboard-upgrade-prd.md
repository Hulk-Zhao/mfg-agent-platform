## 1. 背景与目标

### 1.1 为什么要做这次增量

SPC 过程能力看板是制造质量体系里「**用数据判断过程能力够不够**」的唯一一屏，但当前形态**只够看、不能查、也不能筛**。四个实测事实（均见事实基线 §1–§3）：

| # | 现状 | 用户感知 |
| --- | --- | --- |
| 1 | SPC 屏**零工具栏**（`render_spc` 只渲染 `page-head` + `#spc-crumb` + `#spc-body`），后端 `build_spc_dashboard(registry)` 窗口写死 `DEMO_WINDOW`、端点不接任何 query | 屏上永远只有「最近 7 天」一个固定切片。用户想看「今天」或「本月」，**做不到** |
| 2 | 能力指数侧数据源 `spc_measurement` 仅 **75 行**（3 特性 × 5 子组 × 5 值），只覆盖 `2026-10-13` / `2026-10-14` 两天 | 切「当日」（`DEMO_TODAY = 2026-10-15`）→ **0 行空看板**；切「当月」（10-01~10-15）→ 只有 2 天。**B 组不是锦上添花，是 A 组能用的刚性前提** |
| 3 | `spc_measurement` **连 `line_code` 都没有** → 无法照抄制造看板「产线前缀折工段」的映射法；而柏拉图侧 `quality_defect` **已有** `process_stage` / `product_category` / `defect_category` 三列 | 两块数据维度基础**完全不同** → 必须分别裁决（见 §2.4 / §3.1） |
| 4 | `DRILL_FILTER_SCOPE` **无任何 `spc:*` 条目** → `drillFilterScope` 对 spc 返回 `{}`；`mfgDrillL2Body` 对 spc 走「其余」分支 → 2 级行**直下 L3**，无弹窗 | 即使加了筛选，2 级下钻也不会跟着筛选走（口径漂移）；2 级行一点就跳页，**看不到该特性的完整上下文** |

**一句话**：A（筛选）是入口，B（补数据）是入口**能不能用**的前提，C（弹窗）是交互形态。三者是一条链路，不是三个独立需求。

### 1.2 目标（3 条，正交）

| 编号 | 目标 | 判定标准（可测） |
| --- | --- | --- |
| **G1** | SPC 屏具备**三类分类筛选**（统计口径 3 档 / 产品分类 4 类 / 工段 4 类），且**板级筛选与 2 级下钻同口径** | 三类筛选均可切换；L1 全部卡片 + 2 级看板 + 弹窗**同时**按所选口径与范围重算；同一数字在三处**完全相等** |
| **G2** | SPC 数据量足以支撑三档口径 × 四工段 × 四分类 | 「当日 / 当月 / 最近7天」三档**均非空**；**48 组**（4 工段 × 4 分类 × 3 口径）**每组都有数据**；筛选后**三档判定仍各自可见**（不被筛没） |
| **G3** | SPC 2 级看板行单击 → **弹窗**（能力指数 + 逐日越限 + 原始记录 + 「进入 3 级看板」），且 2 级看板**在真实 UI 中进得去** | 点行**只**弹窗不同时下钻；弹窗数字与 L1 卡片**可对账**；**从 L1 到 2 级再到弹窗三步路径在浏览器里走得通** |

> **G3 的后半句是本轮补充**。原设计只规定了「L2 行点开弹窗」的形态，**从未规定 L2 入口元素是什么** → 实现全对但 2 级看板进不去 → 弹窗在真实 UI 中点不出来，而单测全绿（详见 §4.2，本轮已补契约与验收断言）。

### 1.3 非目标（**本次不做**）

| 编号 | 非目标 | 理由 / 边界 |
| --- | --- | --- |
| **N1** | **不做控制图**（X̄-R / X̄-S / I-MR / C / U 图、失控点标注、控制限与 Cp 联动） | 需引入 `core/spc.py` 之外的控制限内核与多图型渲染，超出增量范围；本次仍只做「能力指数 + 判定」 |
| **N2** | **不做抽样计划**（AQL / 抽样方案 / 接收数 / 拒收数 / 批量检验） | 与能力指数并列的另一套方法体系，需独立数据模型（批量 + 批量接收判定），与「筛选 + 弹窗」无关 |
| **N3** | **不做 MSA 能力分析**（GRR / EV / AV / 重复性再现性 / Gage R&R%） | 需量具与专有内核；本次不引入任何量具维度 |
| **N4** | **不做 SPC 的 L4 / L5**（工序级、工位级下钻） | `spc_measurement` 无工序/工位列；`DEFECT_TYPE_DRILLS` 已把 spc 限定在 entity 维度 |
| **N5** | **不做「缺陷类别」筛选** | 品质看板已有「类别（性能/外观）」；SPC 本次只做「工段 + 产品分类」，避免两屏两套工段白名单语义混淆 |
| **N6** | **不改能力指数算式与判定线** | 双西格玛口径（组内 σ / 整体 σ）与判定线（Cpk≥1.33 合格 / ≥1.00 偏低 / <1.00 不合格）**逐位保持**；本次只调数据量与筛选维度 |
| **N7** | **不做真实产线映射**（`line_code` ↔ 工段） | 能力表无 `line_code`；工段**直接入库**（`process_stage` 列），不做「产线前缀折算」那套静态映射 |
| **N8** | **不扩柏拉图缺陷类型词表** | 现有 10 类缺陷类型是既有红线，柏拉图侧只加筛选维度，**不加新缺陷类型** |
| **N9** | **不做 `product_model`（型号）维度** | 能力表是「特性级」测量表（每特性 25 值），加型号会让同一特性的多型号值混进同一子组 → 组内 σ 被跨型号差异污染 → Cpk 失真且不可对账 |
| **N10** | **不做移动端 / 多端专属布局** | 前端零构建原生 JS，沿用既有 `.chip-row` / `.std-modal` 体系 |
| **N11** | **不做 SPC 专用导出模板** | 报告中心复用既有「就地生成报告」链路 |

## 2. A 组 · 三类分类筛选

> 完整契约（state 变量 / data-* 钩子 / 请求参数名 / 白名单出处）见设计文档 **§1.1**；本章只写**用户可见的行为与口径定义**。

### 2.1 用户可见行为

| 交互 | 控件形态 | 缺省 | 用户切换后应看到什么 |
| --- | --- | --- | --- |
| **统计口径** | 3 个胶囊：`当日` / `当月` / `最近7天` | `最近7天` | 页头 `#spc-window` 的窗口区间变化；**KPI 卡 / 过程能力明细 / 不良柏拉图 / TOP5 全部**随之重算；工具栏右侧提示语写明「KPI / TOP5 / 过程能力明细 / 不良柏拉图 均按所选口径」 |
| **产品分类** | `<select>` 下拉：`全部` + 4 类 | `全部` | 同屏全部模块按该分类汇总；页头出现范围标签「产品分类 X」 |
| **工段** | 5 个胶囊：`全部` / `SMT` / `PCM` / `PACK` / `整机` | `全部` | 同屏全部模块按该工段汇总；页头出现范围标签「工段 Y」 |

**范围标签**：板级范围统一显示为「产品分类 X · 工段 Y」（两段拼接，缺省段不出现）。

### 2.2 口径定义（唯一事实源）

| 概念 | 取值来源 | 落点（见设计文档 §1.3） |
| --- | --- | --- |
| 时间口径三档 | `WINDOWS` 键集 `window` / `day` / `month`（`day`=2026-10-15；`month`=10-01~10-15；`window`=10-08~10-14） | `dashboard.py` 顶部；前端 `SPC_WINDOW_KEYS` / `SPC_WINDOW_CN` 镜像 |
| 工段枚举 | `MFG_STAGES` = SMT / PCM / PACK / 整机 | `dashboard.py`；前端 `MFG_STAGE_CHIPS` 镜像 |
| 产品分类枚举 | `MFG_PRODUCT_CATEGORIES` = 消费电子 / 智能电源 / 储能电源 / 车载 | `dashboard.py`；前端 `MFG_PCAT_OPTIONS` 镜像 |
| 非法取值 | 一律 **HTTP 400**，**不得静默当「全部」** | 端点层 fail-fast（`_checked_window` 模式） |

**两处必须同源的数字**（红线）：

- 「越限率」的分子分母与「能力指数」必须用**同一批测量记录**；
- L1 卡片 / 2 级看板行 / 弹窗三处的 `cpk`、判定、样本数**逐字段相等**。

### 2.3 交互细则（用户可感知的规则）

| 规则 | 内容 |
| --- | --- |
| **换档不复位下钻** | 处于 2 级看板时切换口径 / 工段 / 产品分类，**不退回看板首页**，就地按新口径重取 2 级数据（与订单 / 制造屏一致） |
| **切屏不复用** | SPC 用**专属** state（`spcWindow` / `spcStage` / `spcProdCat`），不复用制造/品质的 `mfg*` 变量 → 别的屏改筛选不会改掉 SPC 的口径 |
| **离线时的诚实** | 后端离线 → 降级演示数据，**必须显式标注**；且提示「离线演示数据不支持板级筛选」（不假装是筛选后的汇总） |
| **筛选无命中** | 显示显式空态「该筛选范围内无测量记录」，**不是 0 值** |
| **未标注数据** | 存量数据的新列为 NULL → 不参与任何筛选的「等于」匹配，但**不传筛选时仍然可见**；屏上要能看出存在未标注数据（`data_gap` / 提示条） |
| **问数跟随** | 屏内「问数」跳转携带当前口径与筛选 → 协同问数回答的数与屏上数一致（否则「看板显示 SMT 的数、问数给全厂的数」＝口径不一致缺陷） |

### 2.4 筛选作用于**哪两块数据**？（主理人补充问题 ② 的正面回答）

**裁决：工段 / 产品分类筛选同时作用于「能力指数表」与「不良柏拉图表」两块数据**，时间口径也同时作用于两块。

| 面 | 数据源 | 维度列现状 | 处置 |
| --- | --- | --- | --- |
| 能力指数 | `spc_measurement` | 无维度列 | **表结构增 2 列**（`process_stage` / `product_category`），按列精确匹配（设计文档 §2.1.1 / §2.2.3 的 `spc_scope`） |
| 不良柏拉图 | `quality_defect` | **已有** `process_stage` / `product_category` / `defect_category` | **零数据改动**，按列精确匹配，与能力表**同一套 scope 声明形态** |

**理由（三条）**：

1. **口径唯一事实源**是本次的硬红线。若筛选只作用能力表，柏拉图还是全厂数 → **同屏两个口径打架** → 正是需求 A 要修的那类缺陷（现状柏拉图「全量无 WHERE」与能力表 7 天窗口不一致，本设计已把柏拉图改为跟随 window）。
2. 两表**都能**支持「工段 + 产品分类」：能力表增列即可，柏拉图表现成；**不构成额外实现成本**。
3. 用户心智：「我只看 SMT 的消费电子」是一个**整体范围**，不是「只看能力表、不看柏拉图」。

**口径副作用（必须在屏上如实呈现）**：能力表与柏拉图表的**测量/检验时间轴不同**（`measured_at` vs `inspect_time`）、**行数基数不同** → 同一范围内两者的「合计」不可互相换算。屏上范围标签只声明「筛选范围」，**不暗示两者可加总**。

## 3. B 组 · 补充数据

> 表结构增列清单、三处 DDL 落点、写入通道兼容、种子策略与守卫见设计文档 **§2.1.1 – §2.1.4**；本章只写**产品口径**：多大规模、覆盖到什么、判定从哪来。

### 3.1 数据规模与覆盖范围（主理人补充问题 ① 的正面回答）

| 项 | 结论 |
| --- | --- |
| **日期覆盖** | `2026-10-01 ~ 2026-10-15`（**必须含 10-15 当日**）。理由：`DEMO_TODAY = 2026-10-15`，而存量 75 行只覆盖 10-13 / 10-14 → 不补 10-15，「当日」口径**必然是空看板**；不补 10-01~10-12，「当月」口径只有 2 天 → **B 组是 A 组能用的刚性前提，不是可选项** |
| **特性规模** | 既有 3 特性（焊点高度 / 锡膏厚度 / 回流焊峰值温度）**取值一字不改**，仅在 10-15 各补一天；**新增 12 个特性**（4 工段 × 3 个：合格 / 偏低 / 不合格 各一） |
| **为何 12 个而非 4 个** | 每工段只有 1 个特性时，筛选命中任一工段后**只剩单一判定档位**（能力看板一筛就「塌」）→「三档判定在筛选后仍各自可见」在种子分布上**不可能成立**。每工段 3 个后，48 组**三档齐备** |
| **规模与落点** | 既有 3 特性 10-15 补 75 行 + 12 新特性 × 4 产品分类 × 3 天（10-10 / 10-12 / 10-15）× 5 子组 × 5 值 = 3600 行 → 合计 **3675 行**，id 段 `4001+` |
| **σ 标定粒度** | 按 **(天 × 产品分类) 批次**反标定（不是整特性一个 σ）。理由：「当日」口径单组合只剩 5 个子组（σ 相对误差约 45%）→ 整特性共用 σ 会让 Cpk 在 [0.60, 2.92] 漂移，48 组里 14 组掉档；逐批次反标定后 48 组全部稳定 |
| **子组纪律** | 每子组恒 5 个值（d2 = 2.326）；同一特性内 (天 × 产品分类) 维度上 `subgroup_no` 唯一 → 跨日期不混样，「当月」口径下组容量恒为 5（不产生静默 Cpk 失真） |

### 3.2 判定口径的来源（**不编造**）

| 概念 | 来源 | 红线 |
| --- | --- | --- |
| **Cpk / Cp / Pp / Ppk** | **只能**由确定性内核 `src/mfg_agents/v2/core/spc.py::compute_capability` 算出 | SPC 相关代码路径**不得出现第二套算式**（源码级断言） |
| **σ 标定** | 种子生成时用 `compute_capability` **反标定** σ，使目标判定档位成立 | 反标定是「让演示数据落到既定档位」，**不是**在运行时按档位反推 Cpk |
| **判定档位** | Cpk ≥ 1.33 合格 / 1.00 ≤ Cpk < 1.33 偏低 / Cpk < 1.00 不合格 | 判定线**逐位保持**（N6） |
| **缺规格限** | 该特性标 `data_gap=true` + 判定「不可判定」+ 能力指数留空 | **绝不编造指数**（宁可空，不可假） |
| **无测量记录** | 显式空态 | **不是 0 值** |

### 3.3 规格限口径（**演示规格限**，见 §5 文案定稿）

| 项 | 结论 |
| --- | --- |
| 既有 3 特性 | 规格限**逐字沿用** `data/seed_v3.sql` 的取值（不重新编造） |
| 新增 12 特性 | 使用**同量纲的演示规格限**（长度类 mm/μm、温度类 ℃） |
| 稳定性纪律 | **同一特性跨日期恒定**（`usl`/`lsl` 是特性固有属性）—— 规格限漂移会让「换统计窗口即换判定」，属真实缺陷 |
| 真实性标注 | UI **必须**显式标注「演示规格限，工艺侧待给定」→ 见 §5 的 4 个落点 |

### 3.4 幂等与老库升级（数据可信度底线）

| 纪律 | 内容 |
| --- | --- |
| **可重复执行结果一致** | 交付种子必须**先删本文件拥有的行、再整批重灌**（`DELETE` 守卫 + `INSERT OR IGNORE` + 显式 id）。`INSERT OR IGNORE` 只保证「同 id 不重复插入」，**不保证「同 id 不残留旧值」** → 老库残留旧版种子时新行被静默跳过（实测少行 + 僵尸特性） |
| **原子性** | 守卫 + 老行回填 + 整批重灌包在**显式事务**里（`BEGIN IMMEDIATE`）→ 重灌中途失败不留「已删未插」的半拉子表（`executescript` 逐语句隐式提交，不加事务会清表）。`BEGIN IMMEDIATE` 而非 `BEGIN`：避免 SQLite 延迟事务的锁升级死锁（读者持共享锁时，`BEGIN` 升级写锁直接 BUSY） |
| **守卫边界** | 「本文件拥有的行」= **归属标记**（`source='demo-seed'` AND `ingested_by='demo'`）**且** id ≥ 4001 → 运行时受治理写入的行（`ingested_by` = 用户 id）**不被误删**；id 段内的用户数据**迁出 id 段**（不删） |
| **老库可重建** | 演示库必须能由「`data/seed_v3.sql` 的 75 行 + 交付种子」**干净重建** |
| **既有 75 行不可动** | 重灌**不得**删掉 `seed_v3.sql` 的既有 75 行；既有 3 特性在默认窗口下必须**仍在**能力表里 |

### 3.5 受治理写入通道的兼容性（主理人补充问题 ③ 的正面回答）

`spc.ingest`（`mcp_tools/tools.py`）是**平台唯一受治理的 SPC 写入通道**。能力表增列必然触及它：

| 面 | 处置 | 向后兼容承诺 |
| --- | --- | --- |
| `spc_store._INSERT_SQL`（现硬编码 10 列） | 扩到 **12 列**，新列写 `process_stage` / `product_category` | — |
| `spc_store.append_measurements` 行构造 | 改 `r.get("process_stage")` / `r.get("product_category")` → **缺键即 NULL** | 老调用（不传维度）**行为逐字段不变**，只是多了两个 NULL 列 |
| `core/spc.py::normalize_measurements` | 增两个**可选**入参，accepted 行带这两个键（缺省 None） | 纯函数、向后兼容；输出行序列的既有键**不被破坏** |
| `spc.ingest` 工具 schema | 增两个**可选**属性（**不在 `required`**） | 工具契约向后兼容；老 Agent 调用不变 |
| 老库写入（表存在但缺新列） | `spc_store.ensure_measurements_table` 增 PRAGMA 守卫 ALTER | 写入通道**自愈老库**，不只依赖 orchestrator 启动时补列 |
| **老数据新列语义** | 老行新列 = NULL → **不参与任何筛选的「等于」匹配**，但**不传筛选时仍可见** | 存量 75 行不需要重灌就能继续用 |

> **总原则**：新参数一律可选、缺省 NULL；既有函数 / 端点在**不传新参数**时行为**逐字段不变**。

### 4.2 **本轮修正的契约**：L1 侧 L2 入口元素（设计盲区兜底）

> 增补位置：设计文档 **§2.3.3-b**（新增小节）与 **§10.3**（新增验收断言 B5）。以下为契约正文，**与设计文档一致**。

**背景**：原设计只规定了「L2 行点开弹窗」的形态，**从未指定 SPC 的 L2 入口元素是什么**。实现方把 L2 行的钩子（`data-spc-modal="capability"`）、绑定排除链、弹窗组件、3 级看板入口**全都做对了**，却**无人提供 L2 入口** ⇒ 浏览器里 2 级看板永远进不去 ⇒ 需求 C 的弹窗在真实 UI 中点不出来，**而单测全绿**（现有守卫只查「代码块里有钩子」，查不出「进不去」）。

**契约**：

- SPC 屏 L1 必须存在**恰好一个**承担「进入 2 级看板」职责的元素，它带 `data-kpi="spc_capability"` + `data-screen="spc"`，且**不得**带 `data-drill-entity`。
- **依据**：`mfgBind` 的 L2 绑定链选择器为
  `[data-kpi]:not([data-drill-entity]):not([data-drill-pareto]):not([data-order-group]):not([data-mfg-modal]):not([data-spc-modal])`
  —— **只有「带 `data-kpi` 且不带 `data-drill-entity`」的元素才会被 L2 链捕获**。
- **对照**：订单 / 制造 / 品质看板的 `mfgKpiCard(UI, k, screen)` **不传 ent** ⇒ 卡上无 `data-drill-entity` ⇒ L2 可达；SPC 因 KPI 卡传了 `k.entity`（逐特性卡）⇒ 若不另设入口，L2 永不可达。
- **落地约束**：
  1. 该入口元素**必须唯一**（多份入口造成「点哪张卡都进 L2」的歧义，且与逐特性卡的 L3 语义冲突）。
  2. 该元素**不得**同时携带 `data-drill-entity` / `data-drill-pareto` / `data-order-group` / `data-mfg-modal` / `data-spc-modal`（任一存在都会被 L2 链的 `:not(...)` 排除 → 点了没反应）。
  3. 逐特性卡与「过程能力明细」表行**保持现状**（带 `data-drill-entity` → 点行直下 L3），本契约**不改变 L1 既有交互**。
  4. 入口元素的**视觉形态由实现方决定**（卡片 / 按钮 / 链接均可），契约只约束「它是哪个元素 / 带哪些 `data-*` / 为何能被事件绑定捕获」。
- **设计铁律（新增，写入即生效）**：凡「点击 X → 触发 Y」的交互，契约必须同时写明「**X 是哪个元素 / X 带哪些 data-* 属性 / X 为何能被事件绑定捕获**」；只描述 Y 的渲染形态 = 会产出「Y 画得完美但进不去」的死功能。

### 4.3 验收断言 B5（本轮新增）

| # | 断言 | 归属 |
| --- | --- | --- |
| **B5** | SPC L1 存在**可被 L2 绑定链捕获**的入口元素（带 `data-kpi="spc_capability"` + `data-screen="spc"` 且不带 `data-drill-entity`）—— **静态断言 + 真机点击可达** | T03.9 |

- **静态断言**（可自动化）：SPC L1 渲染路径中存在**至少一个**同时满足 ① 含 `data-kpi="spc_capability"` ② 含 `data-screen="spc"` ③ **不含** `data-drill-entity` 的元素；且**至多一个**（唯一性）。
- **真机断言**（不可省略）：浏览器打开 SPC 屏 → 点击该入口 → **2 级看板可见** → 点击 2 级行 → 弹窗可见。三步缺一即判失败。
- **反模式守卫**：仅断言「代码块里出现 `data-spc-modal`」**不算通过**（这正是本轮「单测全绿却进不去 2 级看板」的成因）。

## 7. 待确认问题（各给推荐默认值，不卡流程）

| # | 事项 | **推荐默认值（可直接按此实施）** | 理由 |
| --- | --- | --- | --- |
| **Q1** | 工段 / 产品分类筛选作用于**哪两块数据**？ | **同时作用于能力指数表与不良柏拉图表**（时间口径亦同时作用于两块） | 两表都具备该维度（能力表增列 / 柏拉图表现成），不增实现成本；否则同屏两个口径打架，正是 A 组要修的缺陷。口径副作用（两表时间轴与基数不同，不可互相换算）在屏上如实标注 |
| **Q2** | 规格限（USL/LSL）真实性如何标注？ | **演示规格限保持不变 + UI 显式标注「演示规格限，工艺侧待给定」**，4 个落点文案见 §5 | 使用者误把演示规格限当真实工艺规格限＝产品可信度问题；标注不改动数值，避免「编造」与「过度承诺」两端 |
| **Q3** | 筛选切换是否复位下钻层级？ | **不复位**（只改 `drill.window` / `drill.stage` / `drill.prodCat`，就地重取） | 与订单 / 制造屏一致；避免用户每换一次档就被踢回首页 |
| **Q4** | `spc.ingest` 是否本期开放维度写入？ | **开放（可选参数）**，但**不是本期验收项** | 写入通道能落维度是长期正确；但先做只读筛选 + 种子覆盖，工具侧可后置，降低回归面 |
| **Q5** | 柏拉图默认口径由「全量」改为「跟随 window」？ | **采纳**（本次唯一默认行为变化） | 现状柏拉图与能力表不同口径（同屏两个数打架），正是 A 组要修的缺陷；既有断言（10 类、累计单调）仍成立 |

> **Q1 与 Q2 是本轮新增的两个产品裁决**（前者的替代方案「只作用能力表」已否决，理由见 §2.4；后者文案已定稿，见 §5）。
