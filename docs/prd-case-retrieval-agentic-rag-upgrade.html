1. 一页式结论

一句话：案例检索模块已把「安全」做到位（权限前置过滤 + 二次授权 + 引用三元组校验 + 审计哈希链），本次升级要补的是「聪明」与「看得见」——接入大模型作答、把固定管线升级为有界 Agentic 检索闭环，并把本体增强的每一步决策做成前端可回放、可对照的证据链体验，服务对外演示的「眼前一亮」与对内的可信度验收。

2. 背景与问题

2.1 触发场景

平台进入对外演示阶段。案例检索是「AI + 制造业务」故事的主战场：观众（客户管理层、数字化负责人、评审专家）想看到的不是一个搜索框，而是「系统懂制造术语、会像工程师一样多步追查问题、且每个结论都有出处」。现状演示在三个时刻会露怯：

#演示时刻现状表现观众感知
P1问一个跨段问题：「整机段发现的异响，能追到插件段的波峰焊吗？」单次向量召回，跨段关系不存在于检索链路 → 大概率拒答或答非所问「和普通 RAG 没区别」
P2看回答形态模板作答：逐条复述「案例 X 的经验（摘要）：…」，无跨案例归纳、无自然语言推理「这不是大模型，是拼装」
P3追问「你刚才做了什么？」5 步轨迹是静态说明文字，不含「为什么触发再检索、跳了几跳、终止原因」「Agentic 是个宣传词」

3. 目标与产品契约

3.1 产品契约

契约项定义
首要用户① 演示观众（客户 / 评审）——通过「制造案例检索」屏观看或亲自提问；② 现场工程师 / 质量工程师——真实提问并复用案例经验；③ 演示讲解员——需要可预测、可讲解的效果
核心任务用自然语言描述一个制造现场问题，得到有引用、有推理过程、可追问的答案，并能一眼看出「本体增强 Agentic 检索」相对普通检索的差异
触发用户在案例助手屏选定身份后，于「智能问答」页签提交问题（或点击快捷问题 / 案例卡片追问 / 本体查看器「去提问」）
完成条件用户收到回答：每条结论挂可点击的引用三元组；回答下方可展开完整决策证据链（分解了什么、检索了几轮、为什么再检索、为什么停）；或收到带明确原因与下一步引导的诚实拒答
共享业务对象案例（Case）与受控词条（OntologyTerm）——全模块唯一权威定义，沿用在库语义，本 PRD 不重新定义
信任基线权限前置 + 二次授权、无引用不输出、知识层/证据层分离、审计哈希链——本次升级全部沿用，不削弱

3.2 目标（定性，可观察）

  • 观众提出 M1 类跨段问句（「整机段的异响能追到插件段的波峰焊吗？」）时，系统沿「缺陷模式→根因→段」关系完成多跳检索并给出带引用的回答，决策过程可视化回放。
  • 复合问句（「异响 + 装配干涉」）被自动分解为子问句分别检索后归并，而非整句稀释召回。
  • 首轮召回不足时，系统沿本体邻接（同义词 / 父级 / 同根因 / 跨段相似）自动再检索，并在证据链中说明触发原因与终止原因。
  • 演示模式下可开启三方对照：同一问题并列「无本体 / 单跳本体 / 本体增强 Agentic」三组结果与关键数字，差异一眼可见。
  • 无关问题（「食堂几点开饭」）仍被术语闸门与相关度闸门拒答，且拒答附带「相邻概念 / 改写建议」引导——拒答也是可讲解的体验。
本 PRD 不设编造的效果百分比承诺。量化验收沿用《升级方案》§6.2 与 §9 的口径（本体覆盖率 ≥95%、多跳命中率 ≥0.8 配人工相关集、引用可溯源率 100%、既有回归不劣化），指标值以 POC 实测校准为准。

5. 核心流程：有界 Agentic 检索闭环

一次提问的完整旅程如下。蓝色=确定性环节紫色=LLM 可参与的 Agentic 环节绿色=安全内核（不变）

步骤 1 · 确定性
术语归一（全词表）
受控词表（缺陷模式 / 根因 / 对策 / 段）扫描问句，命中即锚定受控码；只影响查询文本，不参与权限过滤（A10）。
步骤 2 · Agentic
意图识别与查询分解
判断问句类型（单点 / 复合 / 跨段追溯 / 对策复用）；复合问句拆为 ≤3 个子问句。输出仅为查询文本片段，不含任何过滤字段。LLM 不可用时退回「整句单计划」。
步骤 3 · Agentic
检索计划
为每个子问句决定：检索动作、返回条数、是否沿本体关系多跳、跳向哪类关系（同根因 / 同缺陷跨段 / 对策复用）。计划中不存在过滤器字段。
步骤 4 · 安全内核（不变）
混合召回（过滤器召回前下推）
权限过滤器由安全内核按身份独立编译并下推；混合检索 + 重排 + 同案例去重，沿用 16 步编排，一行不改。
步骤 5 · 确定性规则为主
充分性评估（自检）
评估命中数、最高/中位相关度、术语覆盖率、关系覆盖（问句要求的关系链路是否都有命中）。给出「充分 / 不足 + 原因」判据。
不足且未触上限 → 沿本体邻接（同义词 / 父级 / 同根因 / 跨段 similarTo）扩查询，回到步骤 4 再检索；跳数 ≥3 或相对收益 < 阈值或预算耗尽 → 终止，如实返回当前结果并写明终止原因
步骤 6 · 安全内核（不变）
二次授权
每条命中回权威 ACL 再判一次，独立代码路径；丢弃计数进入证据链。
步骤 7 · Agentic（LLM）
引用约束作答
仅接收知识层片段（类型闸门运行期断言）；每条结论必须挂引用三元组；支持跨案例归纳——归纳句同样逐句挂引用。
步骤 8 · 确定性（不变）
引用校验与拒答兜底
逐条回查「案例可见 + 内容版本与文本哈希双一致」；无引用 / 校验失败的断言丢弃；全丢即拒答，不编造。
步骤 9 · 确定性
证据链组装与审计
全步骤决策记录（含再检索触发原因、跳数、终止原因、三方对照所需计数）由后端组装进响应；审计只记哈希。

6. 功能需求

FR-01LLM 作答器接入（引用约束生成）P0

目的：把回答从「模板复述」升级为「大模型自然语言作答 + 跨案例归纳」，同时不让生成能力越过引用纪律。这是演示时「这是真大模型」的直觉来源。

触发
检索命中通过相关度闸门后进入作答环节；作答器选择由服务端配置决定，前端无感知。
处理规则
① 作答器实现既有 Answerer 协议：输入 = 问题 + 知识层片段集合，输出 = 「断言 + 引用集合」列表；
② 提示词约束：只允许使用输入片段中的事实；每条断言必须引用至少一个片段；禁止输出片段之外的数字、参数与结论；
③ 跨案例归纳允许且鼓励（这是相对模板作答的核心增量），但归纳句按句挂引用；
④ 输出长度限制 ≤200 字（与 KBQA 输出纪律一致，演示节奏可控）[Assumption, TBD：字数口径待评审确认]；
⑤ LLM 不可达 / 超时 / 输出解析失败 → 自动降级为确定性模板作答，并在证据链中标注「本次为模板降级作答」。
结果与状态
断言进入既有引用校验环节（无引用 / 校验失败即丢弃，全丢拒答）；响应新增作答器标识字段（llm / template），供前端徽标与演示讲解使用。
异常
LLM 超时（阈值 [TBD] 秒）静默降级不报错页；生成内容含未受控数字或案例外事实且被引用校验丢弃时，若剩余断言为 0 → 按既有拒答口径返回，不二次调用 LLM 重试（防成本循环）。

边界：作答器永远拿不到证据层内容（知识层类型闸门既有）；永远拿不到权限过滤器；永远拿不到未通过二次授权的案例。

FR-02有界 Agentic 检索循环P0

目的：把「一次检索定生死」升级为「计划 → 检索 → 自检 → 再检索」的有界闭环，这是「Agentic」的工程定义，也是复杂问句可答的前提。

触发
每次智能问答自动执行；用户无额外操作。
处理规则
① 意图分类（四选一，LLM 参与、确定性规则兜底）：单点查询 / 复合查询 / 跨段追溯 / 对策复用；
② 查询分解：仅复合问句拆分，子问句 ≤3 个；分解产物只允许是查询文本片段；
③ 充分性评估（确定性规则）：命中数、相关度分布、术语覆盖率、关系链路覆盖四项判据，任一不足即给出「不足 + 缺口描述」；
④ 再检索策略由缺口决定：术语覆盖不足 → 同义 / 父级扩展；关系链路不足 → 沿 FR-03 关系多跳；命中不足 → 相邻段扩展；
⑤ 终止条件（硬约束）：本体跳数 ≥3，或本轮相对收益低于阈值 [TBD，待 POC 校准]，或检索预算（总召回次数 [TBD]）耗尽 → 停止并如实返回，证据链写明终止原因；
⑥ 闭环内每一轮召回都完整走「过滤器下推 + 二次授权」，不存在任何绕过安全内核的快路径。
结果与状态
响应中证据链包含每一轮的计划、命中、评估结论、扩展动作与终止原因；最终答案与普通回答形态一致（用户无需理解循环）。
异常
LLM 分解 / 计划失败 → 退回「整句单轮检索」（即现状行为），体验不劣于今天；评估规则异常 → 按「充分」处理进入作答，不阻塞主流程。

红线重申：循环的自由度只在「改写查询文本与决定下一步检索动作」；过滤器由安全内核独占编译（A10）。

FR-03多跳关系推理（本体关系参与检索）P0

目的：让「缺陷模式 ↔ 根因 ↔ 对策 ↔ 段」的显式关系成为检索可以行走的路，使 M1–M5 类跨段 / 跨案例问题首次可答。

触发
FR-02 计划层判定需要关系多跳，或充分性评估判定关系链路存在缺口时。
处理规则
① 关系数据：人工维护的显式关系表（同根因 / 同缺陷跨段相似 / 案例替代 supersedes / 缺陷-段呈现 manifestsOn），沿用词表治理纪律（加载期校验、审批留痕）；
② 遍历深度 ≤3 跳，典型链路：缺陷模式→根因→对策；缺陷模式→段→同段其他案例；案例→根因→跨段同根因案例；
③ 关系遍历产物只是「新的查询文本与候选码集合」，召回仍走安全内核；
④ 对策词表纳入查询扩展（现状仅缺陷模式 / 根因两表参与），使「上次这类问题怎么修」类问句享受本体增强。
结果与状态
命中卡片标注「关系来源」（如「同根因 · 跨段」「对策复用」）；证据链记录每一跳走的关系类型与命中节点数。
异常
关系表缺失或为空 → 多跳步骤在证据链中如实记「无可用关系，跳过」并终止扩展，不影响单跳结果返回。
FR-04决策证据链 trace 2.0P0

目的：把现有 5 步「过程说明」升级为「决策记录」——这是「Agentic 不是宣传词」的可验证证据，全部由后端产出（前端不编数据的纪律不变）。

触发
每次智能问答 / 检索自动产出，随响应返回。
处理规则
每步记录固定结构：步序、中文标题、决策类型（确定性 / Agentic）、输入摘要、关键数字（命中数 / 词条数 / 跳数）、输出摘要；再检索步额外记录触发原因；末步记录终止原因。同时产出三方对照所需计数（FR-06 复用同一数据源，禁止两套口径）。
结果与状态
前端抽屉与「智能体工作台」共用该数据结构渲染；审计侧只记哈希与计数（沿用既有口径）。
异常
任一步骤内部异常 → 该步记录「执行异常 + 已降级」，链路继续；绝不允许因证据链组装失败导致回答失败。
FR-05前端「智能体工作台」（过程可视化）P0

目的：演示的最高光时刻——提问后观众能实时看到智能体「分解问题 → 逐轮检索 → 自检 → 沿本体再检索 → 校验引用」的工作过程，而非一个转圈等待。

触发
用户在智能问答页签提交问题即进入。
处理规则
① 等待期：现有「管线逐级点亮」动画升级为真实步骤流式呈现（流式接口不可用时，降级为响应到达后按证据链逐步回放动画，两种形态视觉一致）[Assumption, TBD：是否上流式响应待技术评审]；
② 回答气泡内：结论句末挂可点击内联引用角标，点击定位到来源案例卡片（复用现有案例卡与详情弹层）；
③ 每轮回答下方保留「智能体检索」抽屉（默认收起）：收起态显示一行决策摘要（分解数 / 检索轮次 / 跳数 / 引用通过数）；展开态为完整证据链时间线 + 本体增强收益面板（沿用现有呈现）；
④ 再检索步骤在时间线上以「循环回退」视觉标识（回流箭头 + 触发原因文案），这是与普通管道的最直观差异；
⑤ 作答器徽标：LLM 作答 / 模板降级作答在回答头部以小徽标区分（诚实呈现，降级也是可讲解的工程决策）。
结果与状态
提问 → 过程可视 → 回答 + 引用 → 抽屉可深挖；多层信息密度按「观众一眼看懂 → 专家逐步验证」递进。
异常
证据链字段缺失时前端只渲染已有字段（不编造补齐）；接口失败 / 401 / 离线沿用现有文案纪律。
FR-06三方对照演示模式P0演示模式

目的：「本体增强 Agentic RAG 到底强在哪」不靠讲解词，靠同题三组结果并列：A 无本体（原文检索）/ B 单跳本体（现状能力）/ C 本体增强 Agentic（目标能力）。

触发
仅演示环境可见：顶栏或案例屏工具区提供「对照演示」开关（默认关闭）；开启后提问以三栏并列呈现。
处理规则
① 三组配置固定：A = 原文直接检索（不归一、无关系、无循环）；B = 现状单跳同义扩展 + 单次检索；C = FR-02 完整闭环；
② 三组跑同一问题、同一身份，权限过滤完全一致（对照的只能是检索智能，不能是可见范围）；
③ 每栏呈现：命中数、Top 命中标题、关键计数（术语命中数 / 跳数 / 检索轮次）；C 栏额外呈现证据链入口；
④ 口径纪律：命中更多不等于质量更高——界面文案沿用「少而准」的诚实口径，禁止宣称百分比提升（数字全部来自当次真实检索）。
⑤ 开关状态仅影响展示编排，不产生第三种检索行为；A/B 两组复用同一安全内核执行。
结果与状态
观众同屏看到「同一句话，三种查法」的差异；讲解员可按栏逐步展开。
异常
任一组执行失败 → 该栏如实显示「本次执行失败」及原因，其余栏正常；禁止用缓存结果冒充当次结果。
FR-07拒答与空结果引导升级P0

目的：拒答是可信度的证明，不该是死路。让「系统不会」变成「换个说法就行」，顺带展示本体词表资产。

触发
相关度闸门拒答 / 检索零命中 / 问题未命中任何受控词条。
处理规则
① 沿用现有「相邻概念引导」组件，扩展触发场景至拒答态；
② 新增问句改写建议：基于命中的受控词条（若有）生成 1–3 个规范术语问法（「你说的『雪花』是不是『锡珠』？」），点击即替换输入重新提问；改写建议只影响查询文本；
③ 拒答原因展示分层：默认一句话人话原因；展开可见分数 / 阈值等技术细节（服务讲解与验收）。
结果与状态

异常
无任何受控词条可建议时，只展示原因与快捷问题，不硬编建议。

7.3 演示讲解锚点（供验收与彩排）
