# 演示访客账号 · 发放与回收说明（T13 交付物）

> 用途：演示环境五访客身份的**发放、使用与回收**操作说明，面向演示组织者。
> 边界（务必先读）：演示环境**免密**——访客不是「密码账号」，而是登录页上的**岗位瓦片**（`[data-role]`）。
> 因此「发放 / 回收」要松在**会话与入口**上，而不是口令上：发放 = 交出演示入口 + 告知选哪块瓦片；
> 回收 = 清会话 + 撤入口 + （必要时）停实例。全部访客为**只读**身份（`readonly: true`），不发起写操作。

## 1. 演示环境入口

| 项 | 值 |
|----|----|
| 本机地址 | `http://127.0.0.1:8004/demo-ui/` |
| 公网演示 | 以隧道地址为准（隧道进程独立于应用实例，**勿动**） |
| 数据来源 | 演示装载层 `GET /api/v2/demo/objects/{name}`（独立合成数据，**不连任何真实业务库**） |
| 演示标识 | 每个接口响应带 `X-Demo-Mode: 1` / `X-Demo-Label: demo-data`，每屏首帧带「演示数据」徽标 |

## 2. 五访客清单（唯一允许登录的演示身份，L-04）

> **L-04 纪律：演示一律只用这五个访客登录。** `cs / hr / fin` 等岗位登录后侧栏**没有**「生态链场景」分组，
> 会让观众以为「屏丢了」。若确需扩岗，改 `SceneRegistry.BUSINESS_ROLES` 一处即可（本节点不改）。

| 访客 id（瓦片） | 姓名 | 部门 | 治理角色 key | 可见场景（spec-v1 §4） |
|-----------------|------|------|--------------|------------------------|
| `gm-demo` | 罗一鸣 | management | `gm` | S1–S6 全量（只读汇总） |
| `biz-demo` | 周予安 | sales | `sales` | S1 / S5（**看不到 S4**） |
| `rd-demo` | 程亦然 | rd_engineering | `rd_engineering` | S2 / S3 / S4（**看不到 S5**） |
| `qa-demo` | 林清和 | quality | `qa` | S3 / S4 / S5 |
| `mfg-demo` | 邵允川 | manufacturing | `manufacturing` | S4 / S6 |

- 可见性由 `roles` 机械判定（`app.js::navVisible`）：`[访客 id] + 治理角色 key` 命中场景 `roles` 才出现在侧栏。
- **S4 仅 gm / rd / qa / mfg 可见；S5 仅 gm / biz / qa / mfg 可见**——这是设计，不是缺陷。
- 五访客登录口令统一为空（免密）；身份换取由 `/api/v2/auth/login` 依治理角色目录签发只读令牌。

## 3. 发放流程（演示前）

1. **起实例**：`uv run python -m uvicorn mfg_agents.v2.demo.api:app --port 8004 --reload`（开发模式）；
   或按 Docker/隧道方案起公网入口。
2. **自检**（发放前必过）：
   - 跑冒烟：`.\.venv\Scripts\python.exe -m pytest tests\demo\test_demo_smoke.py -q`（须全绿）；
   - 跑隔离：`.\\.venv\Scripts\python.exe tools\\demo_gen\\check_isolation.py`（须 exit 0）。
3. **交接入场**：把入口地址 + 本文件第 2 节的「哪块瓦片看哪几屏」一并发给讲解人与观众。
4. **按角色分场**：同一屏给多角色看时，以「主看角色」为主讲（见《演示脚本.md》每场「这屏给谁看」），
   其余角色旁听——避免同一屏多人抢麦。

## 4. 使用中注意事项

- 登录后左侧分组「**生态链场景**」为演示场景入口；点任一数字卡可看「口径 · 出处 · 现算」弹层，`Esc` 关闭。
- 屏内**没有写按钮**：S1 / S2 / S3 / S5 的会签为**只读回放**，S6 的催料待办只展示自动生成结果——
  真实写操作在治理窗口（待办中心 / HITL）执行，**演示访客不得也确实无法旁路写入**。
- 若某屏整块被替换成「已按框架纪律拒绝渲染」面板（`data-sk-badge-guard`），说明该屏**漏挂演示徽标**，
  属开发缺陷，请记录并反馈，勿继续演示。

## 5. 回收流程（演示后）

1. **清会话**：在演示机浏览器执行「退出登录」（清 `localStorage` 中的岗位令牌与身份），或清站点数据。
   —— 免密环境下这是唯一的「注销」动作；不清则下次打开会**直接以原岗位进入**。
2. **撤入口**：关闭公网隧道 / 收回演示地址，使外部不可达。
3. **停实例**（可选，长空闲期）：停掉演示 uvicorn 进程；本机常驻 8004 若为公网隧道入口，按部署约定处理。
4. **清痕复核**：确认演示机未遗留截图 / 导出文件中的**真实企业信息**（本演示数据全为合成虚构，编号带 `DEMO-` 前缀）。

## 6. 安全与隔离红线（发放入场前确认）

- 演示实例**独立配置、独立数据**，不与真实业务库、真实供应商 / 客户数据相连；
  `DemoMarkerMiddleware` 与隔离脚本（A 连接串 / B 凭据 / C 真实企业名词）共同守住这条线。
- 访客令牌为**只读**治理角色，写接口（审批 / 催料 / 会签）不接受访客身份。
- 一切企业人名、客户名、供应商名、编号均为**虚构合成**，可直接对外。
