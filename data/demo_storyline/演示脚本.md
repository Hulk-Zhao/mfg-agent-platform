# 生态链演示 · 解说脚本（T13 交付物）

> 用途：演示环境（`/demo-ui/`）的**逐场景解说词与操作路径**。面向讲解人，不是给观众看的材料。
> 口径纪律：价值表述必须与计划书 §0「价值话术锚点」一致；讲解只讲「**今天怎样 → 之后怎样**」，
> 不堆形容词。行业对标数（如 72h→4.8h）照抄高管版并标注「行业对标，我方基线 Phase 0 实测」。
> 时长纪律：**每场景 ≤ 8 分钟**。本脚本按五访客（gm / biz / rd / qa / mfg）标注「这屏给谁看、讲什么、点哪里」。
> 账号纪律（L-04）：**只用五个演示访客登录**（见《访客账号.md》）；`cs / hr / fin` 等岗位侧栏没有
> 「生态链场景」分组，用它们登录会以为屏丢了。
> 录像已弃（用户裁决 2026-10-20）：本脚本以「现场试讲」为准，不配套录屏。

## 0. 开场与收束（合计约 6 分钟）

- **开场（3 分钟）**：一句话定位——「一个入口，把 16 个部门的协同从**传话**变成**订阅**」。
  演示范围是**生态链六场景**（S1–S6）+ 一张契约骨架屏（S0，仅用于自检，不对观众展开）。
  强调：全场为**只读演示**，访客不发起写操作；屏内每个数字都可点开看「口径 · 出处 · 现算」。
- **收束（3 分钟）**：回到全局话术锚点——「信息不再层层传递：事件直达该处理的人，进展自动同步给该知道的人。」
  「一群人围着问题却产生不了价值，是最贵的浪费——链路通了，围观变订阅。」

## 1. 通用操作路径（每屏都适用）

1. 打开 `http://127.0.0.1:8004/demo-ui/`（或演示隧道地址）。
2. 登录页选**岗位瓦片**（`[data-role]`）→ 点「进入系统」→ 左侧出现分组「**生态链场景**」。
3. 点侧栏 `.nav-item` 进入对应场景屏；**点任一数字卡**弹出「口径 · 出处 · 现算」弹层；
   按 `Esc` 关闭弹层。
4. 每屏首帧右上角恒有「**演示数据**」徽标；看不到徽标的屏说明被框架拒绝渲染（T12 守护），属异常。

## 3. 逐场景解说词

### S1 接单评审（s01） · 预算 7 分钟

- **这屏给谁看**：主看 `biz`（业务）；`gm / rd / qa / mfg` 只读旁听。
- **价值话术锚点**：
  「对客承诺有据：库存、产能、料期自动摆到桌面上，承诺附数据来源。」
  「接单评审从多人多次会变一次会签，材料自动备齐。」
- **讲什么**：一张订单接不接，过去要跑三个部门问四遍；这里三件事一次摆齐——
  ① **ATP 三来源**（在库 / 在制 / 安全库存）现算可用量；② **料期初评**（最晚采购承诺到料 vs 对客交期）；
  ③ **报价区间与成本三分量**（材料 / 工时 / 模具摊销）现算下限与上限。最后是**一次会签**（接单人 / 技术 / 计划三槽位）。
- **点哪里**：
  1. 侧栏「接单评审」→ 首屏「订单与客户」卡（订单量、对客交期、客户）。
  2. 点「**ATP 可用（现算）**」卡看「在库 + 在制 − 安全库存」的现算过程（1,200 + 3,000 − 500 = 3,700）。
  3. 点「**报价下限**」卡看三分量相加校验（169,309.60 元 = 材料 + 工时 + 摊销）；点「报价上限」看毛利缓冲 8%。
  4. 滚动到「订单评审 · 一次会签」，读三槽位留痕（DEMO-EV-0003）。
- **口播佐证数字**：订单量 **5,000 片** · 对客交期 **2027-01-02** · ATP 可用 **3,700 片** · 报价下限 **169,309.60 元**。
- **只读边界**：会签为**只读回放**（未接 HITL 写路径），屏内有「只读演示」标注，如实说明。

### S2 立项（s02） · 预算 7 分钟

- **这屏给谁看**：主看 `rd`（研发）；`gm / biz / qa / mfg` 只读旁听。
- **价值话术锚点**：
  「历史问题库 + 相似案例自动推给评审人；长周期料在立项时提前暴露，不等停线。」
- **讲什么**：立项材料**自动汇总**（订单输入 / EBOM·MBOM / DFM 预审风险项 / 长周期料 / 阶段门计划五个卡片），
  加上**相似历史案例检索**（20 条合成案例，点开可看脱敏原文），最后是**立项会签留痕**（研发 / 工艺双槽位）。
  重点讲：长周期料在立项时提前暴露——**不等停线**。
- **点哪里**：
  1. 侧栏「立项」→ 顶部「立项材料自动汇总」五张卡（订单输入 / EBOM·MBOM / DFM 预审 / 长周期料 / 阶段门计划）。
  2. 点「**长周期料（在途 / 延期）**」卡看「2 张 PO · 延期 1 张 · 缺口 2,000 片」。
  3. 向下滚动到「相似历史案例检索」区，读 20 条案例列表（关键词检索）。
  4. 读「立项会签（研发 / 工艺 双槽位）」留痕（DEMO-EV-0005）。
- **口播佐证数字**：订单输入 **5,000 片** · EBOM/MBOM **4 项** · DFM 风险项 **1 项** · 长周期料 **2 张 PO** · 阶段门 **3 门**。
- **只读边界**：案例检索为**关键词匹配**（非语义检索）；会签为只读回放——按实说明，不夸大「智能检索」。

### S3 阶段门会签（s03） · 预算 6 分钟

- **这屏给谁看**：主看 `rd`（研发）与 `qa`（质量）；`gm / biz / mfg` 只读旁听。
- **价值话术锚点**：
  「良率、CPK、直通率、问题闭环数自动汇成记分卡，评审会从汇报会变成看板会签——用数据证明可以进入下一阶段。」
- **讲什么**：EVT / DVT / PVT 三道试产门的**四维记分卡**（良率 / CPK / 直通率 / 问题闭环数），
  四维全部达标才判 **Go**——**门禁是机械判定，不是人工评审**，每格都能点开复核取值、阈值、来源与算法。
- **点哪里**：
  1. 侧栏「S3 · 阶段门会签」→ 顶部「阶段门概览」四卡（阶段门数 / 主线直通率 / 判定 Go 的门数 / 未决问题）。
  2. 向下滚动到「阶段门记分卡」表格，逐门读 EVT / DVT / PVT 的四维值与阈值。
  3. 点记分卡**任一格**看取值与来源（并附可下拉的检验批：批号 / 抽检数 / 缺陷数）。
  4. 读「门禁机械判定规则」区（全部达标 → Go；恰 1 项不达标且无未决高风险 → 有条件 Go；其余 → No-Go）。
- **口播佐证数字**：阶段门 **3 道** · 主线直通率 **98.77%** · 判定 Go 的门数 **3 / 3** · 未决问题 **0 项**。
- **只读边界**：会签留痕为**只读回放**；「未决高风险」分支在演示数据中无独立标注位（恒为无风险），如实说明。

### S4 批量监控与 ECN（s04） · 预算 8 分钟 · **仅 gm / rd / qa / mfg 可见**

- **这屏给谁看**：主看 `mfg`（制造）与 `qa`（质量）；`rd` 看支线 A 换料影响面；`biz` 不可见。
- **价值话术锚点**：
  「异常不过夜：判异自动拉群取证，处置方案带着成本影响送到会签人。」
  「变更影响面从几天缩短到小时级，该停的没停、该切的没切不再靠 Excel。」
- **讲什么**：两条线——
  ① **主线**：30 天 SPC 序列（含 2 个判异点），判异即时推送**处置会签**（拉群 → 取证 → 方案 → 会签 → 闭环）；
  ② **支线 A**：ECN 换料**影响面四象限**（在制工单 / 库存批次 / 在途批次 / 未发订单行）**逐行可下钻**到原始记录。
- **点哪里**：
  1. 侧栏「批量监控与 ECN」→ 顶部四卡（SPC 序列点数 / 判异点数 / 在制工单数 / ECN 影响面合计）。
  2. 读「SPC 控制图」区：判异点标红，时间轴 09-20 → 10-19，两处判异均在 **2026-10-01 / 2026-10-15**。
  3. 读「判异处置」两张卡（炉温 DEMO-EQ-002「处置中」、ICT 误判率 DEMO-EQ-006「未设会签」），
     点「**处置会签**」看会签槽位与留痕（拉群 ← DEMO-EV-0013；会签 ← DEMO-EV-0014；闭环 ← DEMO-EV-0015）。
  4. 进入「支线 A ECN 影响面四象限」，**逐行下钻**到原始记录。
- **口播佐证数字**：SPC 序列 **30 点** · 判异 **2 个** · 在制工单 **2 张** · ECN 影响面合计 **5 项** · 控制限 **USL 251.0 / CL 245.0 / LSL 239.0**。
- **⚠ 如实说明两处口径差异（原样呈现，不擅自改绑）**：
  ① `DEMO-EV-0019` 的 `object_ref` 是 `DEMO-EQ-006`（equipment 记为「功能测试台」），而 payload 参数写「ICT 误判率」（`DEMO-EQ-005` 才是「ICT 测试仪」）——屏内已显式标注该差异。
  ② 序列判异点与判异处置事件是演示包里**两组独立数据源**，屏内分别按各自口径展示。

### S6 采购执行（s06） · 预算 7 分钟

- **这屏给谁看**：主看 `mfg`（制造）；`gm / biz / rd / qa` 只读旁听。
- **价值话术锚点**：
  「缺料从停线后发现变成到期前预警；催料任务自动挂到采购员待办，谁承诺的交期有据可查。」
- **讲什么**：采购执行链路——PO 下发 → 供应商交期确认 → **缺料预警**（料期 vs 工排需料日比对）
  → **自动生成催料任务**进采购员待办（**零人工步骤**）→ **延期升级链**（每级可追到人）→ 催料留痕表。
  重点讲：**预警到待办间隔 0 分钟**，链路里没有人工环节。
- **点哪里**：
  1. 侧栏「S6 · 采购执行」→ 顶部四卡（采购订单 / 交期已确认 / 缺料预警 / 自动催料待办）。
  2. 读「预警 → 待办自动链路」（DEMO-PO-002 · 间隔 0 分钟 · 人工步骤 0 步；① 预警 DEMO-EV-0027 → ② 催料任务自动生成 DEMO-EV-0028 → ③ 挂采购员待办 孙毅）。
  3. 读「采购订单与交期确认」表：`DEMO-PO-001` 无缺口（已交付闭环）；`DEMO-PO-002` **缺口成立 · 2,000 片**。
     点「缺口判定」格看该笔 PO 的完整口径与算法。
  4. 读「延期升级链」（L1 采购员 孙毅 → L2 采购主管 吴悦 → L3 供应链经理 郑昊）。
- **口播佐证数字**：采购订单 **2 笔** · 交期已确认 **1 / 2** · 缺料预警 **1 项** · 自动催料待办 **1 条** · 缺口量 **2,000 片** · 预警到待办间隔 **0 分钟**。
- **只读边界**：待办**不提供写按钮**——真实催料任务写操作在治理窗口（待办中心 / HITL）执行；本屏只回放自动生成结果，避免绕过治理的旁路写入。
